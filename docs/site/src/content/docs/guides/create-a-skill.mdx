Create a skill on purpose instead of waiting for a correction. The simplest way is to ask your agent in normal chat; you can also run the commands yourself.

## Simplest way: ask your agent in chat

Inside omp, Pi, Claude Code or OpenCode, tell your agent what skill you want:

> *"Create a rematch skill for UX review of checkout and settings screens, and eval it."*

Because your agent has the `rematch` tool (and `rematch` on `PATH`), it runs the workflow for you:

1. **If you already did the work in ≥ 3 past sessions:** it runs `rematch create <name> --from sessions` to distill the skill from your recorded traces.
2. **If it is a brand-new capability:** it runs `rematch create <name> --from description --description "…" --eval-prompt "…"`, checks trigger and `units/` retrieval accuracy for free (`rematch eval trigger <name>`), and runs side-by-side baseline vs. with-skill rollouts behind the validation gate (`rematch eval run <name> --activate`).
3. **If the new skill includes a write-capable script or personal `AGENTS.md` text:** only that part waits for you (`◆ rematch ● 1 needs you`, press `alt+e` → `a`).

## Choose the source (CLI or `/rematch create`)

| You have | Source | Result |
|---|---|---|
| ≥ 3 past sessions that match the name or description | [sessions](#from-sessions), no rollout | provisional |
| a registered task | [task](#from-a-task), one rollout | provisional |
| only a description | [description](#from-a-description), no rollout | draft (promote with `eval run --activate`) |

In omp and Pi, each command below also runs as `/rematch create …` and `/rematch eval …` (with tab completion).
## From sessions

```sh
rematch create <name> --from sessions
```

It searches imported history and traces for sessions whose features match the request; with a lake, every machine's sessions. With three or more, the skill is distilled from what worked and what was redirected.

To pick references by the commands they ran:

```sh
rematch create cargo-test-gate --from sessions --ran cargo,test
```

- Takes sessions whose bash commands contain every word (case-folded, whole words).
- `cd x && cargo test --workspace` matches; `cargo build` does not.
- Best overlap with the name or description first. It still needs 3 sessions.

## From a task

```sh
rematch create <name> --from task --task <task-id>
```

Runs the task once in batch mode (one rollout, no candidates) to obtain a trace, then proposes. This is the only create that costs a rollout. Registering a task: [batch with a verifier](/rematch/guides/batch-with-a-verifier/#register-a-task).

## From a description

```sh
rematch create <name> --from description --description "…" \
  [--branch shared] [--stems stem1,stem2] [--exts tex,md] \
  [--files path …] [--eval-prompt "…" …]
```

The result is a **draft**: visible in the library, never loaded. Re-running `rematch create <name> …` on an existing draft automatically retires the old draft and replaces it, so the agent can iterate on a draft without asking you to disable it first. (`--branch shared` gives the draft `repo_glob: "**"`, and `--stems` / `--exts` set explicit predicate stems and extensions.)

Activate it when you are willing to test it:

```sh
rematch eval run <name> --activate          # side-by-side baseline vs with-skill; promotes on pass
rematch activate <name> --task <task-id>    # runs the task once with it, then provisional
rematch activate <name> --unverified        # provisional on your say-so
```

<Aside type="note" title="Why a description alone is not enough">
No proposal exists without an execution behind it. Editing a harness without one degraded results in the research behind rematch: [D1](/rematch/background/decisions/).
</Aside>

## Evaluate before you activate

`--eval-prompt` (on any `create`) seeds `<entry>/evals/evals.json`; `rematch eval init <name>` creates or extends it later. The suite holds `cases` (a prompt, an optional `expected_output` and verifier) and `trigger_eval` queries that should, or should not, bring the skill in. An Anthropic skill-creator `evals/evals.json` reads as is.

```sh
rematch eval init <name> --prompt "Review the checkout form" --verifier tests
rematch eval trigger <name>                  # free: predicate, retrieval, budgets
rematch eval trigger <name> --fix            # adds suggested stems for missed positive queries & syncs draft edits
rematch eval run <name> --activate           # rollouts: baseline vs with the skill
```

- **`eval trigger`** checks, without a model call, each query against the skill's predicate (precision, recall, pass rate, and the stems a missed query needs), the units `retrieve` would inject for it, every recorded session the predicate would match or miss, and lint: catalog line, description and router bytes, checkable laws, the `Use when …` clause (`evals/` is test material and is excluded from package-text lint). Pass **`--fix`** to apply the suggested missing stems from missed positive `trigger_eval` queries (and sync any on-disk edits to the draft's `SKILL.md` / `rematch.json` into the ledger).
- **`eval run`** runs each case twice in fresh worktrees of `--cwd`'s repo, once with the repo's harness without the entry and once with it (drafts included), judged by the case's verifier (else `--verifier`, else the repo's detected check or tests; `--max-time`, default 180 s). It writes a self-contained side-by-side report to `~/.rematch/evals/<name>/report.html` with `results.json` and the traces, and records a receipt.
- **`--activate`** promotes a draft only when no case regressed and either a case improved on the verifier, or no with-skill verifier failed and every with-skill run completed cleanly and read the skill. The winning trace becomes its evidence.

## What you get

A skill package:

| Part | Holds |
|---|---|
| `SKILL.md` | the router: trigger line and checkable laws |
| `units/` | procedures and pitfalls |
| `facts/` | measured values, each with `as_of` |
| `scripts/` | anything deterministic (non-executable until approved) |
| `evals/` | the eval suite (`evals.json`), never loaded |

Below about 8 KB the package collapses to one file. Layout: [entry layout](/rematch/reference/entry-layout/).
