`~/.rematch/policy.json` holds declared domains, caps, skill place scopes, the omp profiles to skip on import, and the work/home export policy. An absent file means the defaults.

- `rematch policy` writes it: an atomic replace that keeps the other keys.
- With a profile, it is a link to `profile/config/policy.json`, so domains and scopes travel to every machine with `profile sync`.

## Keys

| Key | Shape | Meaning | Written by |
|---|---|---|---|
| `domains` | `[{"match": {"repo_remote": "...", "subpath": "..."}, "domain": "..."}]` | declared domains, first match wins; kept most specific first (with a subpath, then an exact remote, then globs) | `rematch policy domain set\|unset` |
| `caps` | `{"kept_per_domain": <n>}` | kept entries per top-level domain across branches (default 8) | `rematch policy caps set kept_per_domain <n>` |
| `scopes` | `{"<skill name>": {"remote": "<host/org/repo>", "subpath": "<glob>"}}` or `{"<skill name>": {"repo_glob": "<path glob>"}}` | the only place where a skill of that name is exposed ([place scopes](/rematch/concepts/predicates-and-domains/#place-scopes)) | `rematch policy scope set\|unset` (you only; the model's tool and shell are refused) |
| `probes` | `{"daily_runs": <n>, "max_parallel": <n>}` | automatic probe budget (`daily_runs`: probes per 24 h, default 3, `0` = off; `max_parallel`: concurrent probes, default 1) | `rematch policy probes --daily <n> [--max-parallel <n>]` |
| `auto` | `[{"surface": "scripts\|agents\|instructions\|hooks", "scope": "<remote\|path\|**>"}]` | standing rules that auto-approve a surface in matching scopes (instructions still respect `limits.always_on_bytes`), recorded as `"rule:<surface>:<scope>"` in the receipt | `rematch policy auto add\|remove\|list` (you only; the model's tool and shell are refused) |
| `skip_profiles` | `["<profile>", …]` | omp profiles `import --history` skips, merged with `--skip-profile`; such a profile also takes no personal instructions from the profile and contributes none | — |
| `environment` | `"work"` or `"home"` | missing ⇒ home; `library export` refuses at work unless `export_enabled` | — |
| `export_enabled` | bool | allows `library export` at work | — |

<Aside type="caution" title="Gap in the docs">
No `rematch policy` subcommand sets `skip_profiles`, `environment` or `export_enabled` (`rematch policy --help` lists `show`, `domain`, `caps` and `scope`). The docs do not say how those keys are meant to be written.
</Aside>

### `scopes`

One item per skill name. A git place is named by its normalized remote, so every clone and worktree of the repo matches; `subpath` is a glob over the cwd relative to the toplevel (`**`, the default, is the whole repo). A directory outside git is named by a literal path glob (`repo_glob`), which matches it and everything below; it takes no `subpath`.

- An unparseable `policy.json` is an error for every sync that reads scopes, never "no scopes": exposure does not widen because the file did not parse.
- A remote scope never matches a place without a remote.
- A name without an item keeps the default exposure.

## Example

On an empty root:

```sh
rematch policy domain set github.com/acme/web web.frontend
rematch policy caps set kept_per_domain 6
rematch policy scope set bellwether-dev ~/repos/web        # a repo path: its remote is stored
rematch policy scope set web-ui github.com/acme/web --subpath ui
```

leaves:

```json
{
  "caps": {
    "kept_per_domain": 6
  },
  "domains": [
    {
      "domain": "web.frontend",
      "match": {
        "repo_remote": "github.com/acme/web"
      }
    }
  ],
  "scopes": {
    "bellwether-dev": {
      "remote": "github.com/acme/web",
      "subpath": "**"
    },
    "web-ui": {
      "remote": "github.com/acme/web",
      "subpath": "ui"
    }
  }
}
```

On a root without the file:

```sh
rematch policy show --text
```

```text
policy <root>/policy.json (absent)
domains: none declared
caps: kept_per_domain 8
scopes: none (every kept skill is global)
```

How declared domains are used: [domains](/rematch/concepts/predicates-and-domains/#domains). How scopes are used: [place scopes](/rematch/concepts/predicates-and-domains/#place-scopes).
