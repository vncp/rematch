Rematch's binary, shared skills and counters are common. Adapters use each host's own event and skill APIs; they do not make every harness interchangeable.

Reflection model calls and batch rollouts still use **omp**, even when evidence comes from another harness. Session ids distinguish sources: bare omp ids, `cc:`, `codex:`, `pi:` and `oc:`. Pi/OpenCode resume segments add `:r<n>` so finished evidence stays immutable.

**Verified targets:** omp 18.12.6, Claude Code 2.1.285, `@earendil-works/pi-coding-agent` 1.4.0, and `opencode-ai` / `@opencode-ai/plugin` 1.19.4. Old Pi package names and OpenCode 2 are not tested compatibility targets.

Pi and OpenCode acceptance tests launch their **real pinned runtimes** with a local scripted model and isolated state. This proves adapter behavior, not cloud-provider performance or a measured improvement in the agent.

**Look in a terminal UI.** omp and Pi share one renderer (`extension/ui.ts`, host theme colors, every line within the terminal width); RPC and print modes get plain text and the review falls back to one dialog per action. Claude Code, OpenCode and Codex keep their host's own text surfaces.

## Commands per harness

| In Claude Code | Same as |
|---|---|
| `/rematch:rematch-status` | `rematch status` + the skills and agents synced for this directory |
| `/rematch:rematch-review` | walk through waiting actions and automatic changes for this directory, with diffs and bound approve/decline/undo commands |
| `/rematch:rematch-why [cc:<id>]` | `rematch library why` (default: the latest session here) |
| `/rematch:rematch-library` | every entry with its raw counters |
| `/rematch:rematch-mark correction` | overrides the classifier for the last turn of this session |
| `/rematch:rematch-inspect <id>` | `rematch library inspect <id>`: one waiting action in full, with its approve and decline commands |
| `/rematch:rematch-approve <id> --sha <hash>` · `/rematch:rematch-decline <id> --sha <hash>` | the review dialog's Approve / Decline in omp (the session-start message and `/rematch:rematch-review` print both commands with the hash) |
| `/rematch:rematch-off` · `/rematch:rematch-on` | `/rematch off` · `/rematch on` (`on` also re-links the skills for this directory) |

- Only you can run `mark`, `approve`, `decline`, `off` and `on`; Claude cannot invoke them.
- Everything else (`create`, `improve`, `run`, `disable`, `rollback`, …) is the `rematch` CLI in a terminal.
- Codex has no `/rematch` command. The optional `$rematch-status` skill runs the sync, digest and approvals, each command after your approval.
- In omp, most `/rematch <sub>` commands run `rematch <sub>`; `why`, `library`, `inspect`, `disable`, `rollback`, `approve`, `decline`, `mark` and `digest` differ ([the mapping](/rematch/guides/day-to-day/#omp-commands-and-the-cli)). The model's `rematch` tool and its shell commands are refused every user-only control: approve, decline, pin, unpin, disable, rollback, export approval, mark, on, off, uninstall and `policy scope set|unset`.
- Pi uses `/rematch <subcommand>` and a model-facing `rematch` tool with the same user-only refusals. Install with `pi install /path/to/rematch/adapters/pi`.
- OpenCode registers `/rematch-status`, `-digest`, `-inspect`, `-why`, `-library`, `-approve`, `-decline`, `-off`, `-on` and `-mark`. The model-facing tool is read-only. Configure the plugin's checkout path; do not overwrite the rest of `opencode.json`.

## Pi and OpenCode limits

- **Pi:** no native subagent-definition surface. Retrieved context is a hidden custom message that Pi sends as user-role content; it is not counted as a human correction.
- **OpenCode:** no reliable session-end event. Idle ends a run; finalization happens on process disposal, crash reconciliation, or a six-hour quiet-session cutoff. Resume then starts a new segment.
- **OpenCode:** main sessions are traced live; child sessions are imported afterwards. Generated agent profiles and an approval dialog are not implemented.
- **Both:** installation uses a local checkout. Their shared-helper imports are not a standalone npm release. Reflection requires omp; a missing optional harness does not make other integrations unusable.

The adapters' shell checks catch direct attempts to invoke user-only controls. They are not a sandbox against an agent that already has arbitrary shell access.

## How each adapter is wired

| | Claude Code | Codex |
|---|---|---|
| Lives in | `adapters/claude-code/` (a plugin) | `adapters/codex/` (a skill and setup notes) |
| Input | each hook payload, unchanged, piped to `rematch trace-event` / `hook-check` | session rollouts `~/.codex/sessions/**/rollout-*.jsonl`, at import |
| Skills | plugin `skills/` → `~/.rematch/skills` (made at the first `SessionStart`) | `~/.agents/skills/rematch` → `~/.rematch/skills` |
| Fails | never fails a hook except by an intentional block | nothing runs in the session |
