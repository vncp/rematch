### Native Windows portability

The Windows delivery target is the omp integration. `scripts/install.ps1` builds the
binary, creates the native file/directory links, registers the extension and installs
`rematch.exe` in the user's `.local/bin`. Developer Mode or an elevated token is required
for symlink creation. Install/uninstall honor `HOME`, then `USERPROFILE`.

Process lifetimes use an owned Windows Job Object: the child starts suspended, joins
the job, then resumes; timeout or cancellation terminates its descendants too.
Detached jobs either leave a kill-on-close parent job or return an explicit refusal.
Unix retains process groups and SIGTERM/SIGKILL. Locks use OS locks rather than pid-file
ownership; trace writers lock a distant byte on Windows so ordinary readers are not blocked.

For `.cmd`/`.bat` omp launchers, prompts travel unchanged through stdin instead of argv.
Executable launchers and Unix retain the existing argv contract. This applies to both
editor calls and batch rollouts; unbounded shell quoting of model-generated text is not used.

The native CI workflow covers Windows and Linux, including portable process/lock tests.
Windows also runs an isolated PowerShell install → CLI/profile/lake → uninstall smoke.
The omp host and model provider are not exercised by that smoke: its omp shim implements
plugin-management/version operations only. Pi/OpenCode runtime Windows parity remains unverified.

Root `REMATCH_ROOT` = `$REMATCH_ROOT` or `~/.rematch` (shared across profiles). Config root = `~/$PI_CONFIG_DIR` or `~/.omp`. `REMATCH=0` or `REMATCH_ROOT/off` file ⇒ extension registers nothing but `/rematch on` and the `rematch` tool; binary refuses reflect/stage.

`reflect --pending` performs, in order: count (fold all finished traces not yet counted → counters → decide → EXPERIENCE.md), then one reflection per pending file respecting rate limits, then one bounded `lake export` (§19.1; reported under `lake`, an error is logged and reported there, never fatal; absent when built without the `lake` feature). ## 3. Trace schema (extension → binary)

`traces/<session_id>.jsonl`, one JSON object per line, written append-only by the extension:
`{"seq": <u32>, "t": <unix ms>, "ev": "<name>", ...}`. The extension never reads it back.

| ev | fields |
| --- | --- |
| `session_start` | `session_id, cwd, repo (git toplevel or null), branch_hint (basename), model {provider,id}, mode, agent {kind,name}, omp_version, loaded_entries [{id, version, sha}...] (match entries with a predicate hit, minus `retrieve` hooks, which enter through `retrieval`; `sha` = the entry's `content_sha256`; the plain `[id...]` of older traces is still read, `trace::LoadedEntry`), hooks_loaded [id...], staging_dirs [...], repo_remote (origin URL as git prints it, or null; `fold_trace` normalizes it, `identity::normalize_remote`), subpath (cwd relative to `repo`, `""` at the top), head_sha (HEAD at start, null before the first commit), visible_entries [id...] (entries behind the shared skills dir's links, `SkillsSync::visible`, §16)` — ADR 001 identity; the omp extension takes toplevel and HEAD from one `git rev-parse --show-toplevel --verify -q HEAD` and the remote from one `git remote get-url origin` (3 s each, fail open: null) |
| `input` | `text (≤16 KB), source, idle (bool), after_deliverable (last assistant text ≤2 KB or null), prelabel ∈ {"none","interrupt","revert","reprompt","negation","mark:<class>"}, skills_invoked [names from /skill: tokens]` |
| `tool_result` | `tool, call_id, input (JSON ≤8 KB, keys kept, long strings truncated with "…[+N]"), args_hash (sha256 of canonical JSON of full input), result_bytes, is_error, error_class (null | "error"), content_head (first 1 KB of text content), skill_read (name or null), path (input.path/file_path when present)` |
| `tool_blocked` | `tool, call_id, hook_id, reason` (a `block` or `stuck` hook); `args_hash` when written by the Claude Code adapter, whose `stuck` window is read back from the trace |
| `turn_end` | `model {provider,id}, usage {input,output,cacheRead,cacheWrite,totalTokens,cost}, stop_reason, text_head (≤2 KB)` |
| `agent_end` | `turns, is_terminal, yielded` |
| `model_change` | `from {provider,id} , to {provider,id}, reason` (from `retry_fallback_applied` or turn-to-turn change) |
| `mark` | `class ∈ correction|preference|scope` |
| `retrieval` | `entry_ids [retrieve hook ids], units [{entry_id, path (relative to the entry dir), bytes}], bytes` — written when a `retrieve` hook appended a different unit set; `trace::fold_trace` adds `entry_ids` and every `units[].entry_id` to the session's `loaded_entries`, so counting attributes the added context to the hook and to the packages it came from |
| `session_shutdown` | `reasons [...], flagged (bool), files_changed [[path, sha256]...]` — the files successful `edit`/`write`/`multiedit`/`notebookedit`/`apply_patch`/`ast_edit` calls named (`path`/`file_path`/`paths`, and the paths inside an edit or patch payload), hashed at shutdown: the first 50 readable files ≤ 1 MB, repo-relative inside the repo; omitted when hashing overruns its budget (extension 1 s of the 2 s shutdown budget, Claude Code `SessionEnd` 500 ms) or nothing changed (`trace::changed_paths`, `trace::hash_changed_files`) |

Pre-classification (extension, no model; regex constants live in `rematch-core/src/redirect.rs` and are copied verbatim into the extension): `mark` = `/^\/rematch\s+mark\s+(correction|preference|scope)\b/i` (the Claude Code adapter first spells its `/rematch-mark <class>` and `/rematch:rematch-mark <class>` as `/rematch mark <class>`, §18.1); `interrupt` = input while the agent loop is running (between `agent_start` and `agent_end` with `willContinue`; `ctx.isIdle()` is also false while a finished turn settles and over-counted takeovers in live use; the Claude Code adapter: a prompt delivered into a run that had no `Stop` and no Esc abort since its input, §18.1); `revert` = `/\b(?:revert|undo|roll ?back|put it back|git restore)\b|\bgit checkout --(?:\s|$)/i`; `negation` = `/^(?:no|nope|don't|do not|stop|not that|wrong|that's (?:not|wrong)|that is wrong|this is wrong|incorrect|you didn't|you did not|not what i|i said|actually|instead)\b/i` (leading whitespace trimmed); `reprompt` = Jaccard(tokens(text), tokens(previous input)) ≥ 0.6 with tokens `[a-z0-9]+` on lowercased text and at least 6 tokens in the new input ("four" after "three" is not a redo). Precedence: mark > interrupt > revert > negation > reprompt > none.
Session is flagged when any of: ≥1 prelabel ≠ none; `is_error` tool results ≥ 3 in any window of 6 consecutive tool results (tool-error cluster); a `mark` (`trace::flag_reasons`). Flag = write `pending/<session_id>.json`.

Imported sessions get the same trace after the fact (`rematch_core::import::trace_records_of`, the active branch of the omp JSONL): `session_start` (header id/cwd, repo by walking up to `.git`, model of the first assistant message, `mode: "import"`, agent `main` or `sub` for subagent files, `omp_version` from `runtime.version`, no loaded entries/hooks/staging dirs); each user message not attributed to an agent → `input` with the rules above (idle unless the previous assistant stopped `aborted`; slash/`!`/`%` lines other than mark and `/skill:` dropped as live), preceded by `agent_end` for the run it ends; each `toolResult` → `tool_result` paired with its `toolCall` by id; each assistant message → `turn_end` after its tool results, preceded by `model_change` when provider/model changed; then `agent_end` and `session_shutdown` with the flag reasons. Not recoverable from omp JSONL: `input.source` (empty), `branch_hint` beyond the repo basename, `loaded_entries`/`hooks_loaded`/`staging_dirs` (empty), `tool_blocked`, `mark`, retry-fallback `model_change` reasons, `agent_end.is_terminal` (always true). Redirect and error-cluster seqs of an imported ledger row address this synthesized trace.

Claude Code and Codex sessions get the same schema: live from the Claude Code plugin's hooks (`trace-event`, §18.1) and after the fact from their transcripts (`rematch_core::import_claude::trace_records_of`, `import_codex::trace_records_of`, §18).

No trace record carries the session's domain (§6 "Domain"): `session_start` stays as above in the extension and both adapters. The binary decides it from the folded record — `count` (and `reflect`, `create --from task`, `activate`) when it folds a trace, the three importers when they import — so the policy, the branch's `domain.yml` and the inference table in force at that moment apply, and `lake migrate` re-decides it for recorded sessions. Load time knows only the place: `match` reports the place's declared domain as `domain` (§2), which a harness may read but need not echo.

Identity fields by writer (ADR 001): the Claude Code `SessionStart` fills `repo_remote`/`subpath`/`head_sha` by file reads (`identity::identify`: `.git` dir or worktree `gitdir:` file, the common dir's `config`, `HEAD` and refs, no git process), versioned `loaded_entries` from `match`, `visible_entries` from its sync, and `SessionEnd` writes `files_changed`. The three importers fill `repo_remote` and `subpath` from the repo on disk at import time (`identity::session_place`), never `head_sha` or `files_changed` (the import runs after the fact); Codex records its offered rematch skills as `visible_entries` and the loaded ones with version and sha from their `rematch.json`. `count` fills a missing `repo_remote`/`subpath` from the repo on disk (`identity::fill_session`), e.g. an extension trace of a repo without `origin`.

## 6. Predicate semantics (deterministic, same everywhere)

Derivation (binary, on stage): `repo_glob` = the originating session's repo path (exact, as recorded by the extension from `git rev-parse --show-toplevel`) or `**` if no repo; `file_exts` = extensions of files read/edited in the evidence window (≤8); `stems` = up to 10 Porter-stemmed, stop-worded, lowercase tokens ranked by tf-idf against the ledger's session corpus over a weighted document: the originating task turn (the last user input before the redirect) ×2 + basenames of touched files ×2 + the redirect turn ×1. The redirect's own wording ("that's wrong", "every") must not crowd out the task's domain terms, or later sessions on the same task never count (observed on the first real run; fixed in `reflect.rs`). The editor's `entry.stems` are used only when derivation yields nothing: the pre-editor predicate hash is what the rate limits key on.
Place (ADR 001, `predicate::matches_place`): a predicate carrying `repo_remote`, at a place that has one too, matches when the remotes are equal and its `subpath` glob (`None`, empty or `**` = the whole repo) matches the toplevel-relative cwd or one of its ancestors; when either side has no remote the repo glob decides as below. So a worktree or another clone of the same remote matches its repo's entries wherever it lives, and a fork (another remote) does not. `repo_remote` = `identity::normalize_remote` of `origin`, else of the first remote: `host/org/repo`, scheme, user, port, `.git` and trailing `/` stripped, host lowercased, path lowercased on github.com and gitlab.com; a repo without a remote is `local:<sha256 of the main worktree's toplevel>` (linked worktrees share it). Derivation (`predicate::derive`) fills `repo_remote` from the repo on disk and `subpath` = `**`, keeping `repo_glob` as the fallback; `predicate_hash` leaves both out (they restate the glob's repo). The place of `match` is `Place::locate(repo, cwd)` (file reads), of a recorded session `Place::of_session` (its `repo_remote`/`subpath`).
Load-time match (`match --cwd`): the place matches (glob against repo, else cwd, when there is no remote) ⇒ branch dir contributed when ≥1 provisional non-agent, active entry in that branch matches. A `kind: hook` entry is active only while its approved module `rematch-hooks/<id>.ts` exists (`library::hook_active`): before approval it contributes no dir and is listed with `predicate_hit: false`, so it never counts. Provisional agents are listed in every session (omp discovers them from the plugin root regardless of the cwd) with `predicate_hit` = their glob hit, so the trace's `loaded_entries` carries them only where they would count. Both the given path and its `canonicalize()`d form are tried (macOS `/tmp` → `/private/tmp`), on either side.
Triage (`trace::triage`) has two independent axes: *kind* process|content decides whether to propose (content = a corrected prose answer with no tool activity and no process words; anything the agent produced with tools, tool-error clusters, takeovers, reverts and procedural text are process); *scope* domain|invariant picks the editor (domain by default; invariant for error clusters, takeovers, reverts, or text about the agent's general way of working, `INVARIANT_TEXT_PATTERN`). After classification, a session whose only redirects are scope|none and that has no cluster/takeover/mark carries no signal: no editor call.
Count-time match (binary, from a finished trace): place hit (above) AND (`file_exts` empty OR overlap ≥1) AND (`stems` empty OR overlap ≥ min(2, stems.len())). Inputs = first 5 `input` texts + all `tool_result.path` values. An entry whose version `session_start` recorded counts only at that version (`counters::fold_session` matches `(id, version)`; `retrieval` credit stays by id).
Domain (`rematch_core::domain`, no model): a dotted lowercase path (`web`, `web.frontend`, `quant.options`, `3d.animation`) on sessions (`SessionRecord.domain`) and predicates (`Predicate.domain`). Decided by `domain_of(repo_remote, subpath, branch, exts, stems, &DomainPolicy)`, first rule that answers: (1) `policy.json` `domains: [{match: {repo_remote?, subpath?}, domain}]`, first match wins (`repo_remote` equal to the session's or a glob over it, `subpath` a glob over the toplevel-relative cwd or an ancestor; an absent field matches anything; `rematch policy domain set` keeps them most specific first: a subpath, then an exact remote); (2) the session's branch (`library::branch_for`) `branches/<branch>/domain.yml` `domain:`; (3) inference from `improver/domain_rules.toml` (user-editable, shipped like the other improver files): per top-level domain, score = 2 × distinct session extensions in its `[[ext]]` rows + 1 × distinct session stems in its `[[stem]]` rows (table words compared as written and Porter-stemmed); the best wins with score ≥ 2 and a margin ≥ 1 over the runner-up, else `None`; a second level comes only from a `[[stem]]` row of the winner whose stems hit (the most hits, table order on ties). The shipped table: ext `tsx jsx css html vue svelte` → `web`, `swift kt m dart` → `mobile`, `blend fbx gltf usd anim` → `3d`, `parquet sql ipynb csv` → `data`, `rs go c cpp java` → `backend`; stems `backtest sharpe nbbo option strategi portfolio` → `quant`, `anim rig bake skeleton keyframe` → `3d.animation`, `ui component css layout a11y` → `web.frontend`, `ios android swiftui compose` → `mobile`. Gate (`domain::domain_matches`, inside `matches_place`, so load- and count-time): when both the predicate and the place carry a domain, the place's equals the predicate's or extends it at a dot (`quant` matches `quant.options`, never `quantx`; `quant.options` does not match `quant`); absent on either side, nothing is tested, so pre-domain entries and undecided sessions behave as before. Count time uses the session's recorded domain; load time (`match`, `skills sync`) only the place's declared domain (rules 1–2: exts and stems are unknown then), and `match --inputs` the full rule. Derivation fills `domain` from the originating session (`reflect`, `create --from task`, batch winners from the reference rollout); `create --from sessions` and `improve` take the reference sessions' majority (`majority_domain`: a strict majority of those with one on the full domain, else on the top level, else none); `create --from description` decides it for the cwd's place with the description's exts and stems; `transfer apply` gives the copy the target branch's `domain.yml` domain, a `shared` promotion the `common_domain` of the branches' copies (all equal ⇒ it, one top level ⇒ that, else none), an export import keeps the entry's own. `predicate_hash` includes `domain` when present (absent: the pre-domain hash), so a web and a mobile trigger with the same content are two triggers. Declaring: `rematch policy domain set <remote|glob|repo path> <domain> [--subpath <glob>]` (the only writer of `policy.json`); `lake migrate` re-decides every recorded session with the current policy and gives an entry predicate its originating session's domain when that session has one (idempotent). The digest proposes, never applies, one line per undeclared remote where ≥ 5 sessions read skills whose entries share one domain (`common_domain` of the read entries' predicates per session, votes by top level, no tie): `declare domain <d> for <remote>: rematch policy domain set <remote> <d>`.

**Predicate tuning** (`crates/rematch/src/tune.rs`, no model; `rematch tune`, and inside `count` after its decisions whenever it folded a session). A predicate learns from which sessions read its entry, under the same counters.

- *Signals*, per entry over a window (default 6w), from the lake when it holds every journal row this ledger wrote, else from the ledger's journal (the `sessions` rows `report` reads, each its latest row):
  - **read-but-missed**: sessions where `skill_reads` contains the entry's name (the `events.skill_read` key) or a `retrieval` record credited one of its units (checked only for packages, from the session's events file or trace), AND the entry was visible (`visible_entries`; or loaded; or it is a user's skill registered in place, which loads natively everywhere), AND the predicate did not hit (`count_match` false). The model opened it; the stems missed. A read whose session domain the entry's domain does not cover is listed as `cross_domain_reads`, and a read at a place the predicate does not cover (repo glob, remote, subpath) as `cross_place_reads`; neither is evidence: a tune never widens a domain or a place.
  - **matched-but-unread**: sessions where the predicate hit and the entry was loaded, but no `skill_read`/retrieval of it occurred. (Hit, loaded and read = `matched_read`.)
  - Loaded/visible test an entry id on its own machine; a session of another machine loaded it by `content_sha256`.
- *Proposer* (no model): read-but-missed ≥ 3 → new stems = current ∪ (task-turn stems of those sessions present in ≥ 2 of them), ranked by tf-idf (`features::rank_stems`, tf = sessions carrying the stem) against the window's sessions, capped at 10 (current stems first); `file_exts` = current ∪ observed (cap 8; an empty list stays empty — it already matches every extension). Matched-but-unread ≥ 4 and read-but-missed < 3 → drop stems that occur in the unread sessions' stems but in none of the read sessions' (most unread sessions first; keep ≥ 2 stems; never empty). Domain: an entry without one whose read sessions carry exactly one domain, in ≥ 3 of them, gets it (a narrowing); an existing domain never changes; stems are never unioned across domains (the widening uses only the sessions the target domain covers; with no target and read-but-missed sessions in two domains, no widening). No change → no proposal.
- *Guards* (`tune::check`, all evaluated by `--dry-run` too): a sibling entry (same files, `version+1`, `sibling_of`, `status_note: "predicate tune: +[..] -[..] from N session(s)"` — added stems, `.ext`s and `domain=<d>` after `+` —, origin `Import{source:"predicate-tune"}`, status provisional, `tune` = the change and its evidence) — never an in-place edit; at most one tune per entry per 7 days (`last_tune_at` on the entry) and one pending tune sibling per entry; never on pinned/built-in/hook entries, nor on anything but a provisional or kept skill (or rule) entry; the sibling's staging slot (`staging/<branch>/<name>`) must be free, so a provisional rematch-owned parent is tuned only after its own canary keeps it (one pending version per name); never remove `repo_remote`/`repo_glob`/`subpath`; never produce `**`; stems ≤ 10, exts ≤ 8, stems ≥ 2 after a narrowing; lint and rate limits apply unchanged (new predicate hash = new canary; a kept-cap `NeedsMerge` does not block, since a tune revises an existing entry, which is what that signal asks for). The tune is itself counted and can be retired, and keeps/replaces v1 through the existing anchor path (§7: its `sibling_of` names the parent; the keep takes the parent's kept slot). Every tune writes its evidence (session ids per signal) into the proposal row (`{decision: "PREDICATE_TUNE", entry, tune, from, to}`) and `rematch.json`, records an admission on the new hash, and sets the parent's `last_tune_at`; nothing else of the parent changes.
- *Reading it back*: `library why` shows `predicate tune v2 pending (<id> · <note> · matched … recurrence … harm …)` under the parent's line while the sibling is provisional; `report` lists every tune in the window (§19.3).

`content_sha256` (entry identity across machines): sha256 of `{"files":[[path, sha256]…]}` over the entry dir's files sorted by `/`-separated path, without `rematch.json`, `EXPERIENCE.md` and hidden files, with the `rematch:` frontmatter block removed from SKILL.md / AGENT.md (`library::content_sha256`); set at stage, at keep (also a ledger-only keep of a foreign entry) and when `improve` or `import --forge` registers an existing skill or lesson; `rematch lake migrate` fills it on older entries.

## 7. Counters and decisions (SPEC §loop 7–8, verbatim)

Per matched session (predicate hit while the entry was in `loaded_entries`): `recurrence += 1` if a redirect of the entry's `redirect_class` occurred (classifier output, or prelabel ∈ {revert, negation, mark} when class unknown); `harm += 1` if a new tool-error cluster, an `interrupt`, or a user `disable` happened. Tokens/turns recorded.
Decide: `matched ≥ 4 && recurrence == 0 && harm == 0 → Keep`; `recurrence ≥ 2 || harm ≥ 2 → Retire`; `matched ≥ 12 → Dormant`; `provisional for 30 days && matched < 3 → Dormant`; `Kept && harm ≥ 2 within 30 days → Retire`; else `Continue`. Per-family breakdown kept; if one family shows harm ≥ 1 and another has matched ≥ 2 with zero harm/recurrence, the entry is split (Phase 3): the harmed family gets a sibling proposal.
Implementation notes (`counters.rs`): each matched session contributes 0/1 recurrence and 0/1 harm (one row per (entry, session)). Prelabel mapping when the classifier gave no class: `revert|negation|mark` → correction, `mark:<class>` → that class; `interrupt|reprompt|none` → no class; a classifier `none` means no class. An entry without a `redirect_class` (motivated by an error cluster or takeover, and the built-ins of §10) recurs on a correction or preference redirect; a scope redirect (the user widened or changed the task, which `trace::triage` also treats as carrying no failure signal) never counts as its recurrence. Harm = `error_clusters > 0 || takeovers > 0 || disabled`. Rule order: pinned ⇒ Continue; provisional: Retire, Keep, Dormant(12), Dormant(30 d since `status_since`, < 3 matched); kept: ≥ 2 harm events in the last 30 days and since it became kept ⇒ Retire. Count-time match uses `repo` (else `cwd`) against the glob, where a glob also matches descendants of the path it names. A `retrieve` hook is in a session's `loaded_entries` only through a `retrieval` record (§3), i.e. only in sessions where it injected units; `session_start.loaded_entries` never lists it.
Anchor replay (SPEC §Rollback and anchors; research D17, HCL b=1; `scope/anchor.rs`): a Keep of an entry that *replaces* a kept entry — its `sibling_of` names a kept entry, or keeping it takes the kept slot (`<skills>/<name>/`, agents `kept-agents/<name>/`) a kept entry holds, which `library::set_status` would supersede (rematch-owned entries only) — first replays the kept entry's originating task once. Anchor task, first with a verifier: the kept entry's `Origin::Task`, the replacing entry's, then a task in the kept entry's branch (any task for `shared`) whose last `runs/<task>/receipt.json` lists the kept entry (`staged[].id`, `staged[].merged_into`, `next_run[].id`, or the reference rollout's `loaded`); verifier = the task's own, else its last run's `job_spec.verifier`. The replay is one rollout (`batch::rollout::run_rollout`, label `anchor-<short id>`, the task's first seed, solver role) under the task's run lock: base library for the task repo minus both entries, the replacing entry's files as the only candidate. Pass ⇒ the keep proceeds and the replacing entry gets a receipt `Certificate{lint, canary: its counters, verifier: <verdict>}`. Fail ⇒ Retire with `status_note` `anchor replay failed: task <id> (<verifier>): <detail>`; the kept entry stays; the reflector input carries `anchor_replay`. No anchor task with a verifier ⇒ `NoVerifier`: the counters (the canary) are the anchor and the keep proceeds. A replay error (task locked by a running run, omp missing) fails the decision; the entry stays provisional and is decided again at its next matched session. Every replay record (task, verifier, verdict, rollout summary) goes to the blob store; the `count` envelope's decision carries `anchor: {kept, replay, certificate?}`. There is no anchor suite.

## 8. Rate limits

Per predicate_hash: ≤1 admission per UTC day; no reflection while a provisional entry with the same predicate_hash exists (pending canary). Per branch: ≤10 provisional; 5 kept general + 5 kept per branch before a new candidate must merge/revise (near-duplicate by simhash(normalized text) Hamming ≤ 6 or identical script body ⇒ append evidence to existing entry). Per top-level domain (§6 "Domain"): ≤ 8 kept entries across every branch on this machine (`policy.json` `caps.kept_per_domain`, `rematch policy caps set kept_per_domain <n>`). ≤3 model calls per reflection (classifier batch, editor, one lint-retry).
Implementation (`rate::can_admit(ledger, predicate_hash, branch, domain, kept_per_domain, now)`, checks in this order): pending canary (any provisional entry with the predicate_hash) → `PendingCanary`; an admission today (UTC) → `DailyPredicate`; ≥ 10 provisional in the branch → `BranchProvisionalCap`; kept cap → `NeedsMerge {branch, general, branch_kept, domain, domain_kept}` (for branch `shared`: ≥ 5 kept in `shared`; otherwise ≥ 5 kept in the branch; or, when the candidate's predicate has a domain, ≥ `kept_per_domain` kept non-built-in entries whose predicate domain has the same top level, any branch). `NeedsMerge` is a routing signal: the caller merges/revises via `dedup::route_duplicate` instead of dropping the candidate. Built-in entries (§10) are neither canaries nor counted against the caps.

## 9. Editor channel (`omp -p`)

argv (forge contract): `omp --cwd <tmp> --model <provider/id> --no-tools --system-prompt <improver/editor.md> --config <improver/omp-no-tools.yml> --no-prewalk --no-session --no-title --no-extensions --no-skills --no-rules --no-lsp --mode json -p -- <prompt>`; env adds `PI_OFFLINE=1 PI_SKIP_VERSION_CHECK=1 PI_TELEMETRY=0`; own process group; timeout (default 180 s) ⇒ SIGTERM group, 2 s, SIGKILL group. ## 10. Extension (`extension/index.ts`, no build step)

Factory (async): read env/off; resolve binary (`$REMATCH_BIN` → `<ext>/../target/release/rematch` → `<ext>/../target/debug/rematch` → PATH); `pi.exec(bin, ["match","--cwd",cwd])` and `pi.exec(bin, ["skills","sync","--cwd",cwd,"--harness","omp"])` in parallel (5 s each); override `skills.customDirectories` with `[...configured, ...dirs]` (`dirs` of the sync = the shared `REMATCH_ROOT/skills`, §16 "Shared skills"); remember `entries`/`hooks` of the match (a failed sync leaves the hooks adopted, a failed match leaves the skills added); register tool `rematch {operation, arguments[]}` (approval: read for doctor/status/library/digest/match/why, `builtins ls`, `transfer suggest`, exec otherwise), command `/rematch`, shortcut `alt+e` (digest), handlers §3. `session_start`: open trace, write `session_start` (`staging_dirs` = the skill dirs added), spawn `reflect --pending` detached (`Bun.spawn` with `stdio ignore`, `unref`), run `digest` and present lines via `ctx.ui.notify`, and each approval via `ctx.ui.confirm(title, diff)` → `library approve|decline <id>`. `/rematch <sub>`: `why|status|library|create|improve|run|activate|mark|off|on|disable|rollback|approve|ship|transfer|builtins|anchor` map 1:1 onto the binary; long ones return a job id. **Re-match.** The loaded set (entries, hook modules, added skill dirs) is matched and synced again — and the hook sets swapped atomically, serialized with any in-flight match — when a main session's `ctx.cwd` differs from the cwd last matched (at `session_start` and on the next `context` event), on `session_switch`/`session_branch`, and after a successful `library approve|disable|rollback` or `activate` (digest approvals included), so an approved hook runs from the next tool call or request, not the next omp start; skill links a re-sync adds reach omp's skill list at its next start (discovery ran once, after the factory). The module-level `match` + `skills sync` cache (shared by subagent rebinds, keyed by binary + cwd) is cleared on a switch/branch and after those operations, so no cached result outlives the session it was matched for; a failed match or sync is not cached and leaves the previous set in place. A session's `session_start.loaded_entries` is what was loaded when it started: an entry approved mid-session runs at once and counts from the next session. Hook modules are imported as `<path>?v=<mtimeMs>` so a rewritten module is a new module record (Bun ignores the query of a `file:` URL for its module cache, so the path is used as is).

**Profile sync at session start** (§20). `match` reports `profile_present` (`REMATCH_ROOT/profile/.git` exists). The first main `session_start` of a process whose match saw a profile starts `pi.exec(bin, ["profile","sync","--timeout","8"], {timeout: 10 s})` in the background (not awaited; once per process; no exec at all without a profile); a failure or `offline: true` is logged and the session goes on. What it pulls loads in the next session (omp scanned its skills at process start).

**Hook modes.** A compiled hook module (`library::hook_module`) is data only: `export default { id, mode, tool, field, regex, message, pass_condition, params }`, `params` = the resolved mode parameters (`HookRule::params`; for `block` the JS regex `{source, flags}`, a leading Rust `(?i)` becoming the `i` flag). The extension validates the shape (`hookFromModule`; an invalid module is skipped with a warning) and implements the modes; `tool: "*"` matches every tool.

| mode | event | behavior | on failure |
| --- | --- | --- | --- |
| `block` | `tool_call` | `input[field]` (a string) matches the regex ⇒ block with `message`, trace `tool_blocked` | closed: a throwing check blocks with `rematch hook <id> failed: …` |
| `stuck` | `tool_call` | the extension keeps the session's last 32 calls as `tool\0args_hash` (sha256 of canonical JSON, as in the trace); a call whose `repeats` immediately preceding calls are identical to it is blocked with `message` (trace `tool_blocked`). Any different call in between resets the run, so re-running a command after an edit passes; a call a `block` rule rejected never ran and is not recorded (one `stuck` rejected is, so the next identical call is rejected too). Reset on every session start | closed |
| `truncate` | `context` | walking back from the newest message, age = non-synthetic `user` messages after a `toolResult`; when age > `max_age_turns`, the result's text blocks become one block with the first `keep_chars` UTF-16 code units (one fewer when the cut would split a surrogate pair) + `\n…[rematch: truncated N chars, age K turns]` (N = code units removed); image blocks stay; several rules ⇒ the smallest `keep_chars`. A fresh object replaces the message in the outgoing array only | open |
| `retrieve` | `context` | main sessions with a trace only. Query = the last non-synthetic user message text + the paths (`arguments.path`/`file_path`, selectors stripped) of the toolCalls behind the last 10 `toolResult`s, ≤ 16 KB. `pi.exec(bin, ["retrieve","--cwd",ctx.cwd,"--budget",B,"--min-overlap",M,"--query",q], {timeout: 3000})` — no `--entries`: the binary already bounds candidates to the entries loaded for `--cwd`; the result is cached per argv. When units come back, ONE message is appended: `{role:"custom", customType:"com.vncp.rematch.retrieval", display:false, timestamp, content, details:{units:[{entry_id,path}]}}` with content `[rematch] Units of skills loaded in this session that match the current request, retrieved by the harness (the whole skill: skill://<name>).` followed by one `<unit skill="<name>" path="<path>">…</unit>` per unit; omp sends it as a `developer` message (§0). The same message object (same `timestamp`) is re-sent while the unit contents are unchanged. A changed unit set writes one `retrieval` trace record, the only way the hook enters `loaded_entries` (§7). Several retrieve hooks ⇒ the first one's parameters, every one's id in `entry_ids` | open: a failed or slow call adds nothing |

`truncate` and `stuck` also run in subagent sessions (like `block`); `retrieve` needs the main trace to attribute what it added. Handlers never throw; the `context` handler returns `undefined` when it changed nothing.

**Built-in entries** (`crates/rematch/src/builtins.rs`; SPEC §Isolation, research D22/D23). The context policies are shipped as three ordinary hook entries, not as always-on extension behavior: branch `shared`, repo glob `**` with no exts/stems (they match every session), `Origin::Import{source:"builtin"}`, family `unknown/unknown`, each with a SKILL.md router (trigger line, laws, pitfalls) and `hook.json`:

```json
{"mode":"retrieve","tool":"*","message":"rematch: units of the loaded skill packages that match this request.","pass_condition":"A request that shares no stem with a loaded package's trigger line, or whose loaded packages hold no unit sharing 2 distinct stems with it, passes unchanged; units only ever come from entries this session loaded, and at most 6000 bytes are added.","budget_bytes":6000,"min_overlap":2}
{"mode":"truncate","tool":"*","message":"rematch: old tool outputs trimmed in the outgoing request.","pass_condition":"Tool results at most 6 user turns old, and any result of at most 1200 characters, reach the model unchanged; the session file always keeps the full output.","max_age_turns":6,"keep_chars":1200}
{"mode":"stuck","tool":"*","message":"rematch stuck-detector: this exact call (same tool, same arguments) already ran 3 times in a row. Change the approach: different arguments, a different tool, or ask the user.","pass_condition":"Every call that differs from the call immediately before it passes, and so do the first 3 repetitions of any call; re-running a command after any other call (an edit, a read) passes.","repeats":3}
```
(`context-unit-retrieval` [D22], `tool-output-truncation` [D23], `stuck-detector` [D23]). `builtins::ensure` runs from `AppCtx::open_with` after the improver install: one read of `REMATCH_ROOT/builtins.version` (hash of the shipped specs) when nothing changed; otherwise, under `.builtins.lock`, it stages every built-in whose name has no built-in entry yet and rewrites the marker. A failure is logged to stderr and never fails the command. A retired, declined or dormant built-in is never re-staged automatically; `rematch builtins reinstall [name…]` stages a fresh provisional version (version + 1, `predecessor`) of each built-in that is not live, and `builtins ls` lists them with status, approval and counters. They arrive provisional and **unapproved**: the digest offers each as a hook approval (the module text as diff, reason = trigger line + pass condition). An unapproved hook entry is inert in full (`library::hook_active`): it contributes no branch dir, `match` reports `predicate_hit: false` (so it never enters `loaded_entries`), and no module exists. Approved, a built-in counts like any entry. It carries `redirect_class: None` on purpose: it was motivated by no particular redirect, so every correction or preference redirect in a session where it ran counts as recurrence, and error clusters, takeovers or a disable count as harm; two of either retire it (§7). A scope redirect does not count: the user widening or changing the task says nothing about a context policy. That makes a context policy prove itself against everything the user corrects while it is active. `context-unit-retrieval` is credited only where it acted: the extension leaves retrieve-mode hooks out of `session_start.loaded_entries`, and the hook enters a session's `loaded_entries` through the `retrieval` record (§3) written when it injected units. Built-ins take no admission-cap slot and are no pending canary (`rate::can_admit` skips `library::is_builtin`), and `ship --scope team` never selects them automatically.

## 11. Deviations from SPEC (all forced by §0)

1. `resources_discover` → factory-time `skills.customDirectories` override (same semantics, per process).
2. Batch isolation uses a `--config` overlay + fresh worktree instead of a private `PI_CODING_AGENT_DIR` (auth lives in the agent dir).
3. `omp plugin install @<org>/rematch` → `scripts/install.sh` (`cargo build --release`, `omp plugin link extension/`, PATH shim). No registry publish.
4. "Related thing: embeddings, exploratory only" is not implemented: the binary holds no provider credentials; exact signature + MinHash are implemented.
5. Status `pinned` is carried as the `Entry.pinned` flag (status and location unchanged; automatic transitions refuse pinned entries; `disable`/`rollback` are user actions and proceed). `Status::Pinned` remains a valid status for imports.
6. A kept entry replaced by a sibling becomes `dormant` (files in `predecessors/<name>/<version>/`) rather than `retired`, because `rollback` must be able to restore it and `retired` never leaves. A non-rematch skill that a kept entry replaced is saved as version `0` and restored by `rollback`/`uninstall`.
7. Declining an approval (`library decline`) retires the entry (SPEC: retired ← "approval declined").
8. Provisional agents cannot load "on match": omp discovers task agents only from fixed dirs (§0), so they load through the plugin root in every session and are counted where their glob hits. `off` does not unload them (omp reads the plugin's `agents/` itself); `library disable` or `omp plugin disable` does.

## 12. lint.toml schema

`improver/lint.toml` (copied to `REMATCH_ROOT/improver/` on first run). Every key is optional; a missing key takes the built-in value (`rematch_core::lint::DEFAULT_LINT_TOML`, which the shipped file equals verbatim — a test enforces it). All `[patterns]` entries are Rust `regex` syntax; use TOML multi-line literal strings (`'''…'''`) for patterns containing `'` (inside `'…'`, `''` is **not** an escape).

```toml
[limits]
always_on_bytes = 8192   # per branch, this entry + LintContext.branch_other_bytes: SKILL.md bodies (frontmatter excluded), AGENT.md `description` values, AGENTS.fragment.md files
max_stems = 10           # predicate.stems
max_exts = 8             # predicate.file_exts

[patterns]               # rule ids in brackets
session_id = [...]       # [identifiers] UUIDs (v4/v7), omp session file names
user_names = [...]       # [identifiers] home-dir paths that reveal a user; plus LintContext.user_names (literal, case-insensitive, word-bounded)
task_paths = [...]       # [identifiers] task-specific absolute paths (/Users, /home, /tmp, /var/folders)
urls = [...]             # [executable_risk]
network = [...]          # [executable_risk] curl, wget, nc, ssh, scp
pipe_shell = [...]       # [executable_risk] curl|wget … | sh
destructive_git = [...]  # [executable_risk] push -f/--force, reset --hard, clean -fd
string_match_user = [...] # [string_match_user] branching on the user's literal words
approval = [...]         # manifest.rationale matching any ⇒ executable_risk findings are Warn ("approval requested"), else Error
order_exception = [...]  # manifest.rationale matching any ⇒ form_order findings are Warn, else Error

[form]
order = ["trigger", "laws", "procedure", "pitfalls", "facts"]
[form.headings]          # lowercase substrings of a ##-heading that classify it; unclassified headings are ignored
trigger = ["trigger", "when to use", "scope"]
laws = ["laws", "rules", "invariants", "constraints"]
procedure = ["procedure", "workflow", "steps"]
pitfalls = ["pitfalls", "anti-patterns", "gotchas"]
facts = ["facts", "workspace facts", "reference"]

[hooks]
probes = ["echo ok", "cargo test", "git status", "README.md", "src/lib.rs"]  # a hook regex matching "" or every probe "matches everything"
```

Rules (`LintFinding.rule`): `identifiers`, `string_match_user`, `executable_risk` (applied to every file in the entry dir except `rematch.json` and `EXPERIENCE.md`; markdown is linted with its `rematch:` frontmatter block removed; `hook.json` contributes only `message` + `pass_condition`); `trigger` (non-empty repo glob, stem/ext caps, non-empty trigger line present in the SKILL.md body or any `Use when…` line, non-empty `description`; for `kind=agent` the document is `AGENT.md`: frontmatter `name` equal to the entry name and not `main`/`sub`, non-empty `description`, no trigger-line or form-order check on the system prompt); `scripts` (every `scripts/<path>` referenced in markdown exists; no script executable unless listed in `Entry.approved_scripts`); `always_on`; `form_order` (trigger line, then classified headings, non-decreasing in `form.order`); `facts_as_of` (`facts/*.md`, and SKILL.md of `kind=fact`, need frontmatter `as_of`); `hook` (`lint::hook_problems`, per mode: every mode a rule, a non-empty pass condition and a tool (`*` = any), no parameter of another mode; `block`: field, message, regex compiles and does not match everything; `stuck`: message, `repeats` in 2..=20; `truncate`: `max_age_turns` 1..=100, `keep_chars` 200..=100000; `retrieve`: `budget_bytes` 500..=65536, `min_overlap` 1..=20; non-block modes take no regex/field; `hook_module` refuses the same problems); `fragment` (`AGENTS.fragment.md` non-empty, no `#`/`##` heading outside a code fence: it is appended under `## rematch: <name>`); `fork_path` (`Entry.fork_path` repo-relative without `..`, `library::validate_fork_path`); `transfer` (`LintContext.transfer` and a domain lesson or fact). `LintReport.ok` iff no Error.

### Binary behavior notes (Phase 1 + 1.5)

- Scripted model (`--editor <cmd>`): run with `sh -c`, prompt on stdin, env `REMATCH_ROLE=<role>` and `REMATCH_PROMPT=editor|classifier|reflector`; stdout is the reply. Without it, the role's model is resolved from config.yml and called through `run_no_tools`. The reflector uses the `rematch-editor` role with `improver/reflector.md`.
- Model calls: `count` makes ≤ 1 batched classifier call per pass (skipped when there are no unclassified non-mark redirects) and one reflector call per keep/retire (deterministic EXPERIENCE record when it fails). Each reflection's `CallBudget(3)` is charged for the classifier when its session was in that batch, then editor + one lint retry. A failed editor call keeps the pending file (`attempts` counter; dropped after 3).
- Detached jobs: the child of `spawn_detached` writes its final envelope into `jobs/<id>.json` (`status: done|failed`, `result`); a live status whose pid is gone reads as `lost`. `run-worker` manages its own record. `REMATCH_JOB_ID` is stripped from every `run_bounded` child.
- Ownership: an entry owns its directory iff it lives under REMATCH_ROOT or its SKILL.md carries a `rematch:` block with its id (`reflect::owns_dir`). Registered skills (`import --forge`, `improve`) and lessons are *foreign*: decisions, disable and pin are recorded in the ledger only (`reflect::record_status`), never moving or rewriting their files; their EXPERIENCE.md goes to `REMATCH_ROOT/brownfield/<id>/`; approve/decline/rollback refuse them.
- `import --forge`: skills register in branch `forge` with `path` = the forge skill dir; each `learnings/*.md` becomes a provisional `lesson` at `REMATCH_ROOT/lessons/forge/lesson-<slug>/` (`LESSON.md` copy + `rematch.json` with `evidence_sha256` = blob hash of the file, `source_path`). `match` omits lessons. `import --history` keeps an existing `source: trace` session row (richer) instead of overwriting it, and records the session file as `source_path`; `count` folding a synthesized trace refreshes the import row's signals and keeps it `source: import` (counted once, never replaced by a trace row).
- `improve`: the audit counts every ledger session with the skill in `skill_reads` (traced and imported); < 5 ⇒ `{refused, traced_sessions, offer}`. The excerpt and clusters come from each signalling session's live trace, else the trace synthesized from its omp session file (`import_cmd::records_for_session`: recorded `source_path`, else `<agent dir>/sessions/<cwd slug>/*_<id>.jsonl`, else a scan); the moment is the most recent session's earliest undismissed redirect, else the first cluster of the session with the most error clusters; `clusters` lists redirect clusters and `error_cluster` groups (failing tools, error heads). Siblings share the base predicate (no pending-canary check), get `sibling_of` and stage at `staging/<branch>/<name>/` where branch = `--branch`, else the reading sessions' common repo, else `shared`.
- `create --from sessions`: request stems (name + description) and `--files` extensions vs. session stems/exts; a session matches with overlap ≥ min(2, |request stems|); ≥ 3 needed; up to 8 references. `activate --task` runs one reference rollout and attaches its moment as evidence before draft → provisional.
- `digest` lines: one per entry whose status changed since `REMATCH_ROOT/digest.last` (imported registrations summarized in one line), plus Scope review/stale/transfer lines; approvals = unapproved scripts or uncompiled hooks of owned provisional/kept entries (hook reason = trigger line or manifest rationale + `Pass condition: …`), plus `export:<id>` items. `digest.last` advances to the later of the run's start and the newest status time shown, so an entry the same process changed (built-ins installed on a first run) is not shown twice. Shown by omp at session start (notifications + approval dialogs) and by the Claude Code `SessionStart` hook (§18.1 "Digest").
- `reflect` content-triage failures are logged (stderr + envelope) and the pending file deleted; no ledger proposal row.

### Shared skills (`REMATCH_ROOT/skills/`)

One directory delivers skill entries to every harness: `REMATCH_ROOT/skills/<name>` → the entry dir (`staging/<branch>/<name>/` or the kept `~/.omp/agent/skills/<name>/`). `library::sync_shared_skills` writes it; `rematch skills sync --cwd <dir> [--harness omp|claude-code|codex]` runs it for a cwd (its repo, else itself) and returns `{added, pruned, total, dirs, links, untouched, off, …}`.

| Harness | Reads the shared dir through | Synced for a cwd by |
| --- | --- | --- |
| omp | `skills.customDirectories += [REMATCH_ROOT/skills]`, set in the factory (per process, §10) | the factory (`skills sync --harness omp`) |
| Claude Code | the plugin's `skills/ → REMATCH_ROOT/skills` (created or re-pointed at `SessionStart`) | the `SessionStart` hook (`reloadSkills: true` when a link changed, §18.1) |
| Codex | `~/.agents/skills/rematch → REMATCH_ROOT/skills` (one link the user makes; Codex scans user roots recursively, §18.2.1) | `skills sync --harness codex --cwd <repo>` before Codex starts (§18.2.3) |

- **What is linked.** Every kept or pinned entry (status `kept`/`pinned` or the human pin), and every provisional entry whose predicate matched a cwd that was synced — the load-time rule of `list_for_match` (repo glob against the repo, else the cwd; hooks only once approved). Only entries rematch owns (their dir holds their own `rematch.json`; a user skill registered in place is never linked) with a `SKILL.md`; agents go through `agents/` (Subagents row), lessons are library records. A link targets the entry's recorded path, so a skill kept under one omp profile's agent dir loads in every profile (`REMATCH_ROOT` is shared, §1). With a profile (§20) every `profile/skills/<name>/` holding a `SKILL.md` is a kept source too — kept here, kept on another machine, or adopted — and fills any name no entry holds.
- **Loading is the union of the branches used on this machine.** A sync adds the cwd's matches and never removes a provisional link because this cwd does not match it: another session, in another repo or another harness, may be loading it.
- **Pruning.** A link goes when its entry stops being provisional/kept/pinned (retired, dormant, stale, back to draft, deleted) or moved (a keep re-points it to the kept dir), and every link goes while rematch is off. Every status change runs the sync without a cwd — `set_status` (keep, retire, dormant, stale), `stage`, `activate`, `rollback`, pin/unpin, `off`/`on` — so a retirement leaves the dir at once and a keep re-points at once; only a cwd sync adds provisional links.
- **Counting is unchanged.** Each session's `loaded_entries` still comes from `list_for_match` for its own cwd (Codex: the import's count-time predicate, §18.2.3): an entry loaded through the shared dir whose predicate misses the session is not counted. The union therefore costs one description line per extra skill in the system prompt and never a counter.
- **One name, one link.** A provisional entry matched by the current sync takes its name; a provisional candidate already linked shadows the kept entry of the same name until it is kept or retired; kept/pinned entries fill every other name. Non-symlinks in the dir are never touched (`untouched`); hidden names are skipped.
- **Atomic and idempotent.** Each link is written as a hidden temporary symlink renamed over the name, so a reader sees the old target or the new one, never a missing name; a sync with nothing to change writes nothing (`added` and `pruned` empty).
- **Race rule.** Syncs run without a lock: each only adds links to live entries and removes links to dead ones, so concurrent syncs converge; two matching cwds wanting different entries under one name leave the last writer's link; a prune re-reads the link and removes it only while it still points where the sync saw a dead entry. A session sees the dir as of its own skill scan (omp at process start, Claude Code at `SessionStart` or its re-scan, Codex at session start); a link pruned under a running session dangles there — retirement wins over a running session, and a link added later reaches the session's successors.
- **Migration.** The first sync removes the per-harness link dirs of older versions, `REMATCH_ROOT/claude-skills/` and `REMATCH_ROOT/codex-skills/` (their links; a dir holding anything else stays). `--harness codex` also re-points `~/.agents/skills/rematch` and `<repo>/.agents/skills/rematch` when they still point at `codex-skills`, and removes the kept copies older versions wrote under `~/.agents/skills/<name>/` (marker `.rematch-codex.json`); `uninstall` removes the shared dir (links only, never their targets) and any such copies.

## 17. Batch mode (Phase 2, `crates/rematch/src/batch/`)

New `Entry` field (serde default, omitted when false): `pending_next_run` — a batch winner staged by a `run` of its `Origin::Task`, decided by that task's next run.

Task (`tasks/<id>.json`): `{id, repo (absolute), prompt, verifier?, max_time_secs (default 600), tools?, seeds (default [1]), created_at}`. omp has no sampling seed: the seed names the workspace and is exported to the rollout as `REMATCH_SEED`.

Verifier specs (`run --verifier`, else the task's): `tests` (Cargo.toml → `cargo test`; pyproject/pytest.ini/setup.* → `python3 -m pytest -q`; package.json + bun lock → `bun test`), `parity:<produced>=<expected file | sha256>`, `receipt:<path>` (JSON `verdict: pass|fail`, optional `score`), `[script:]<cmd>` (`sh -c` in the worktree, exit 0 = pass, last stdout JSON line with `score` supplies the score). Verifiers run with env `REMATCH_TASK`, `REMATCH_WORKTREE`, `REMATCH_REPO`, capped at max(task cap, 60 s).

Rollout: `git worktree add --detach <variant>/wt HEAD` (plain `cp -R` for a non-git repo); the harness (kept/pinned entries + provisional entries `list_for_match` loads for the repo, candidates shadowing same-named entries) is written to `<variant>/skills/<name>/`; `--config <variant>/overlay.yml`:
```yaml
skills: {enabled: true, enableCodexUser: false, enableClaudeUser: false, enableClaudeProject: false, enablePiUser: false,
         enablePiProject: false, enableAgentsUser: false, enableAgentsProject: false, customDirectories: ["<variant>/skills"]}
memory: {backend: "off"}
memories: {enabled: false}
```
(keys from `omp config list`, omp 18.12.6; a probe showed only the custom-dir skill to the model). argv = `omp::tools_argv` with the `rematch-solver` role (→ `default`), env `child_env()` + `REMATCH_SEED` + `REMATCH=0`, bound = task cap + 60 s. stdout → `events.jsonl` (+ ledger blob); the stream must pass `verify_stream` (else verdict Fail "rollout invalid" without the verifier; a time-capped rollout is still judged). `events_to_trace` maps `session` → `session_start`, `message_end` user/assistant/toolResult → `input`/`turn_end`/`tool_result` (input recovered from the toolCall block), `agent_end`; the worktree path is rewritten to the repo.

Worker (`run-worker`): reference rollout (pending entries of the task loaded) → next-run rule: entries with `pending_next_run` and `Origin::Task{task}` go `kept` (+ `verified_on`, receipt) on a reference pass, `retired` on a fail; a pass for an entry that replaces a kept entry first runs its anchor replay (§7; the run's omp binary, this task's lock reused when the anchor task is this task): replay fail ⇒ `retired` with the `anchor replay failed: …` note and the kept entry stays, replay pass ⇒ `kept` plus a second receipt with the anchor verdict, replay error ⇒ the flag stays for the next run; the row in `next_run` carries `anchor: {kept, replay, certificate?}` → if the reference passes a score-less verifier the cycle stops (nothing can rank above it) → k invariant + k domain editor calls (`editor.md`; input = §9 shape with `redirect {class: correction, text: verifier detail}`, `task.prompt`, `verifier.verdict`, `prior_candidates` for i > 1; excerpt = around the longest consecutive tool-error stretch, else the trajectory tail), each linted and probed once → every (invariant, domain) pair composed: the best pair by one editor call with `scope: compose` (+ `candidates`, `behavioral_diff`) while the model-call budget lasts, the rest (and composer KEEP_BASE/failure/lint failure) by deterministic merge (union of files; domain laws that are simhash near-duplicates of an invariant law dropped; same-named entries merged) → each composed harness runs once; with ≥ 2 composed variants the best runs once more and must pass both → selection: (pass, score) desc, then tool errors, turns, lesson count, order; a winner must pass and beat the reference, else KEEP_BASE → winner lessons: a near-duplicate of a branch entry appends evidence to it; else one `rate::can_admit` per winner, staged provisional (origin Task, branch/predicate of the task repo, `lesson_tag` by scope, `pending_next_run: true`, receipt with the verdict). Budget at width k: rollouts = (k+1)² + [k>1] (4 at k=1, 10 at k=2), model calls = 2k + 1; anchor replays are outside it (one per replacing pending entry) and are not in the receipt's `rollouts`. Progress in `jobs/<id>.json` (`phase`, `rollouts_done`, `rollouts_budget`, `model_calls`, `verdicts`); receipt `runs/<task>/receipt.json` (+ blob) with every rollout summary, proposal, lint report and the decision; workspaces and worktrees are removed after the receipt (also on failure). One run per task at a time (`runs/<task>/.lock`).


## 18. Adapters

One binary, one ledger, one lint and one set of counters and entries serve every harness. Adapters normalize host events into the trace schema (§3); cheap runtime checks stay in the adapter when the host requires an in-process handler, while admissions, reflection and counters stay in Rust. Session ids are namespaced: omp uses bare ids, Claude Code `cc:<id>`, Codex `codex:<id>`, Pi `pi:<id>`, and OpenCode `oc:<id>`. Pi and OpenCode may add `:r<n>` for a resumed segment so finished, counted evidence is never overwritten. `import_cmd::Transcripts` routes history, `reflect --history`, `improve` and lake export through the corresponding parser.

### 18.1 Claude Code (`adapters/claude-code/`)

**Verified facts** (Claude Code 2.1.285: `claude --help`, `claude plugin --help`, `claude plugin validate`, `claude --plugin-dir <dir> plugin details <name>`; the hooks, skills and plugin references at code.claude.com/docs; the CHANGELOG versions in brackets):

- A plugin is a directory with `.claude-plugin/plugin.json`; `hooks/hooks.json`, `commands/*.md` and `skills/<name>/SKILL.md` are its default component locations. One session: `claude --plugin-dir <dir>`. Every session: a plugin directory under `~/.claude/skills/<name>/` loads as `<name>@skills-dir` (`claude plugin init` help text). `~/.claude/plugins/` is the marketplace cache (`installed_plugins.json`, `cache/`), and settings know only `enabledPlugins` keyed `name@marketplace`; a marketplace install copies the plugin and drops symlinks that leave it, so it is not a route for this adapter.
- Command hooks in exec form: `command` + `args` [2.1.139], `${CLAUDE_PLUGIN_ROOT}` substituted and exported. Payload on stdin; common fields `session_id`, `transcript_path`, `cwd` (follows `cd`/worktrees), `hook_event_name`, `permission_mode`, plus `agent_id`/`agent_type` when a subagent's tool fires the hook. Event fields: `SessionStart` `source` (`startup|resume|clear|compact|fork`), `model` (optional); `UserPromptSubmit` `prompt` (as typed; also fired for background-task reports and cross-session messages); `PreToolUse` `tool_name`, `tool_input`, `tool_use_id`; `PostToolUse` + `tool_response` (successful calls only); `PostToolUseFailure` + `error`, `is_interrupt` [2.1.119]; `Stop` `last_assistant_message` [2.1.47] (not fired on a user interrupt); `StopFailure` (API error) [2.1.78]; `SessionEnd` `reason`.
- Exit 2 on `PreToolUse` blocks the call and Claude reads stderr as the reason; any other non-zero exit is a non-blocking error; exit 0 with one JSON object on stdout is structured output. `UserPromptSubmit` `hookSpecificOutput.additionalContext` adds context next to the prompt; above 10,000 chars Claude Code moves it to a file. `SessionStart` `hookSpecificOutput.reloadSkills: true` re-scans skill directories after the SessionStart hooks [2.1.152] (discovery normally runs before they finish). `SessionEnd` hooks get 1.5 s; a plugin's `timeout` does not raise that budget (`CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` does).
- A plugin's `skills/` that is a symlink to a directory elsewhere, and symlinked skill folders inside it, are followed by a session: `claude plugin validate` says so ("A session loading this plugin does follow it") and `claude --plugin-dir … plugin details` listed the skills behind both kinds of link. Plugin skills are namespaced `/<plugin>:<skill>` (the `Skill` tool's `skill` input is `rematch:<name>`).
- A plugin's `agents/*.md` load from a real file: probed with `claude --plugin-dir <probe> plugin details` (2.1.285, `CLAUDE_CONFIG_DIR` pointed at a temp dir), an agent file inside a symlinked `agents/` directory is listed, a symlinked agent file (in a real or a symlinked `agents/`) is not. `REMATCH_ROOT/agents/` holds file symlinks (`<name>.md → staging/…/AGENT.md`), so the plugin cannot link it; it gets copies instead ("Agent loading" below), which `plugin details` lists (`Agents (1)  log-triage`, live smoke).
- Commands substitute `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_SESSION_ID}` [2.1.9] and `$ARGUMENTS`, and run ``!`cmd` `` lines before the prompt reaches the model when `allowed-tools` pre-approves them; `disable-model-invocation: true` keeps a command from the model's `Skill` tool.
- `SessionStart` output: `hookSpecificOutput.additionalContext` reaches Claude before the first prompt; the universal `systemMessage` is shown to the user (in `-p --output-format stream-json` it arrives only inside the `hook_response` event, live smoke). No field opens a dialog or asks a question.
- A prompt typed while Claude works is queued and delivered into the running run at the next tool boundary (transcripts: `promptSource: "queued"` after a `tool_result`); `UserPromptSubmit` fires at delivery, before that run's `Stop` (live smoke: `-p --input-format stream-json`, a second message sent 3 s into a `sleep 6` call). An Esc abort fires no hook; Claude Code writes a user entry `[Request interrupted by user…]` to the transcript.
- In `-p` mode Claude Code kills async hooks still running at teardown; work that must outlive the session has to be detached from the hook. A `--plugin-dir` plugin takes the name of a `skills-dir` plugin of the same name for that session (`rematch@skills-dir: Not loaded — the name "rematch" is already taken`), so a smoke test can load a copy of the adapter.
- Transcripts: `~/.claude/projects/<slug>/<uuid>.jsonl`, subagents under `<uuid>/subagents/agent-<id>.jsonl` (`$CLAUDE_CONFIG_DIR` relocates `~/.claude`). Format facts relied on: module doc of `rematch_core::import_claude`.

**Plugin.** `hooks/hooks.json` wires `UserPromptSubmit`, `PostToolUse`, `PostToolUseFailure`, `Stop`, `StopFailure`, `SessionEnd` to `sh scripts/hook.sh trace-event`, `SessionStart` to `sh scripts/hook.sh session-start` (`trace-event`, then the reflection below) and `PreToolUse` to `sh scripts/hook.sh hook-check`. `hook.sh` pipes the payload unchanged to `rematch <op> --harness claude-code --hook-output` (binary: `$REMATCH_BIN` → `<repo>/target/{release,debug}/rematch` → `PATH`, as the omp extension; `scripts/rematch.sh` also exports `CLAUDE_PLUGIN_ROOT` = the plugin when unset, so the commands find it) and never fails the hook: it exits 2 only for an intentional block (binary exit 2 with nothing on stdout), prints stdout only on exit 0, and exits 0 otherwise. Under `--hook-output` the binary prints the hook reply (`data.hook`: stdout JSON, stderr, exit) instead of the envelope, and every error, including a usage error, exits 0. `commands/rematch-*.md` run, through ``!`…` `` lines: `status` (`--text status` + `--text skills sync --harness claude-code`), `why` (`library why [$ARGUMENTS]`), `mark` (`mark --session cc:${CLAUDE_SESSION_ID} --class $ARGUMENTS`), `library` (`library ls`), `approve` / `decline` (`library approve|decline $ARGUMENTS`), `off` (`off`), `on` (`on` + `skills sync --harness claude-code`); `mark`, `approve`, `decline`, `off` and `on` set `disable-model-invocation`. They hold no prompt text beyond "show the output". `create`, `improve`, `run`, `disable`, `rollback`, `ship` and the rest stay shell commands.

**Reflection.** `hook.sh session-start` starts `rematch reflect --pending` after the `session_start` record is written, as the omp extension does at session start: `set -m; nohup … </dev/null >/dev/null 2>&1 &` — its own process group, no stdio, so the hook returns without waiting and the run outlives a `-p` session; the binary's `pending/.lock` keeps it to one run. It starts only when omp is found (`$OMP_BIN`, else `omp` on `PATH`): the editor and classifier are `omp -p` calls (§9), and a failed call uses up a flagged session's attempts. Starting after the record matters for `resume`: the trace ends with a `session_start` again, so `count` (`finished`: a `session_shutdown` after the last `session_start`) waits for the resumed run and counts the session once, whole. The model calls run in that detached process, never inside the Claude Code session. Live smoke: a session flagged by a negation in its resumed half was counted with that redirect and reflected at the next start.

**Digest.** At `SessionStart` (not `compact`) the binary runs `rematch digest` (which advances `digest.last` for every harness, as omp's session-start digest does) and, when it has lines or approvals, replies `systemMessage` (the lines, then one line per approval: `<kind> <name>: /rematch:rematch-approve <id> · /rematch:rematch-decline <id>`, and `rematch library approve|decline <id>` for a shell; ≤ 4,000 chars) and `additionalContext` (the same text, an instruction never to approve or decline on the user's behalf, and each approval's reason and diff so Claude can show them; ≤ 9,000 chars). There is no one-tap approval: Claude Code hooks cannot ask.

**Skill loading.** The plugin's `skills/` is a symlink to the shared dir `REMATCH_ROOT/skills/` (§16 "Shared skills"), created at the first SessionStart (the repo cannot ship an absolute link, so `adapters/claude-code/.gitignore` lists it) and re-pointed if an older version left it at `REMATCH_ROOT/claude-skills`, which that first sync deletes. `SessionStart` and `rematch skills sync --harness claude-code --cwd <dir>` (which also fixes the plugin link when `$CLAUDE_PLUGIN_ROOT` is set) run the sync; kept entries are linked there from `~/.omp/agent/skills/<name>/`, so nothing is copied into `~/.claude/skills/`: nothing outside `REMATCH_ROOT` and the plugin directory is written, and `rematch uninstall` (which removes `REMATCH_ROOT`) leaves only the dangling `skills` link in the plugin.

**Agent loading.** Claude Code lists a plugin's agents only from real files, so `skills_cmd::sync_plugin_agents` (at `SessionStart` and in `skills sync --harness claude-code`, plugin = `$CLAUDE_PLUGIN_ROOT`, else `<CLAUDE_CONFIG_DIR or ~/.claude>/skills/rematch`) copies every provisional agent (omp offers each staged one in every session) and every kept or pinned one into `<plugin>/agents/<name>.md` (git-ignored; a provisional agent wins over a kept one of its name). The copy keeps `name`, `description` and the body, maps an omp `tools` list to Claude Code names (`read` → `Read`, `bash` → `Bash`, `find`/`glob` → `Glob`, `fetch` → `WebFetch`, `task` → `Agent`, …; unknown names dropped, none left = the field is dropped), keeps `model` only as a Claude Code alias or `claude-…` id (an omp role such as `@smol` is dropped: the session's model) and drops other keys. `agents/.rematch` lists each copy (`{"<name>.md": {"id", "sha"}}`): a copy is rewritten or pruned only while its bytes are what the sync wrote, a file of the same name that is not a copy is left alone (and the entry not copied), and an empty `agents/` is removed. A retired agent's copy goes at the next sync, not at the status change; `uninstall` removes the listed copies and the marker. Whether a copy written by a start's own hook is offered in that session is not established (agents are read as the session starts), so `loaded_entries` credits only agents whose copy was listed before that start's sync (live smoke: the first session wrote the copy and did not count it; its resumed half did).

**History.** `rematch_core::import_claude` (`scan_sessions_dir`, `parse_session`, `trace_records_of`, `session_record`, `find_session_file`): typed prompts (`origin.kind` absent or `human`, not `isMeta`/compaction summaries/injected frames/local command output; `[Request interrupted by user…]` marks an aborted run, so the next prompt is `interrupt`; a queued prompt is `interrupt`; `<command-name>/x</command-name>…<command-args>a</command-args>` → `/x a`) → `input`; `tool_use` + `tool_result` → `tool_result`; entries sharing `message.id` → one `turn_end` (thinking blocks dropped, `<synthetic>` model ignored); `agent_end` before each prompt and at the end; `session_shutdown` by `flag_reasons`. Subagent transcripts have no `input`s (their user text is the parent's) and are never reflected. `import --history --harness claude-code|all` folds each transcript into a `source: "import"` row; outcomes are not extracted (they come from omp tool receipts). The importer keeps the import rule of §3 (a prompt after an aborted run is `interrupt`, as for imported omp sessions); the live adapter follows the live rule (an abort ends the loop, so only a prompt delivered into a running loop is `interrupt`).

**What Claude Code cannot do** (compared with the omp extension):

1. `truncate` hooks: no hook rewrites earlier tool results or the outgoing request. `PostToolUse` `updatedToolOutput` [2.1.121] replaces a result only as it arrives (age 0), while `truncate` shortens results once they are `max_age_turns` user turns old, so `truncate` entries are not run and not counted.
2. `retrieve` runs once per prompt, not before every model request, and the injected units stay in the conversation (omp re-sends one non-persisted message per request); a unit set equal to the last one is not injected again.
3. Skill loading is not per process: the shared dir serves every Claude Code session (and omp and Codex), holding the union of what every synced cwd matched, and a concurrent session sees links added after its scan only after its next re-scan. Its trace still lists, and counts, only what was matched for its own cwd.
4. No per-turn event: `turn_end` records are recovered at `Stop` from the transcript tail, which can lag; then one `turn_end` without model/usage carries `last_assistant_message`. Model fallbacks inside a run are seen only as turn-to-turn model changes.
5. Esc fires no hook: the abort is read from the transcript at the next prompt (`[Request interrupted by user…]`), and that prompt is not a takeover; a session that ends right after Esc closes the run at `SessionEnd`. A prompt queued while Claude works is a takeover only because `UserPromptSubmit` fires when it is delivered into the run (verified facts above); if a release delivered it after `Stop`, it would be idle.
6. The `stuck` window sees completed calls only (parallel identical calls in flight are not counted); subagents get `block` rules but no `stuck` detection.
7. Hooks cannot open dialogs: the digest is a `systemMessage`/`additionalContext` at session start and approvals are commands the user runs (`/rematch:rematch-approve <id>`, or the shell); there is no one-tap approval, and no `rematch` tool for the model (Claude can run the CLI through Bash; the approve/decline/off/on/mark commands are not model-invocable). Reflection runs detached from the `SessionStart` hook and needs omp for its model calls; without omp it is `rematch reflect --pending` from a shell (or the next omp session start) after configuring the roles.
8. Agent copies are refreshed at `SessionStart` and `skills sync --harness claude-code` only, so a status change reaches Claude Code at the next start; omp-only frontmatter (`model` roles, unknown tools, other keys) is dropped from the copy.
9. A session killed before `SessionEnd` (or past its 1.5 s budget) keeps an unfinished trace that `count` skips — the same failure mode as an omp crash.
10. Imported Claude Code sessions carry no `loaded_entries` (transcripts do not record what the plugin linked).
11. Batch mode (`run`, anchor replay) drives omp rollouts only (`batch/worker.rs`, `Substrate::rollout_cmd` are omp-typed, the plan for another harness is §18.2.4).

#### 18.2.3 Delivery: `skills sync --harness codex [--cwd <repo>]`

3. Migration from the per-harness layout of older versions: a `rematch` link in those roots still pointing at `REMATCH_ROOT/codex-skills` is re-pointed (atomically) at the shared dir, and the kept copies under `~/.agents/skills/<name>/` marked `.rematch-codex.json` are removed (kept entries reach Codex through their links now); `uninstall` removes such copies too.

Codex has no per-session gating: every link is visible in every Codex session, whatever its repo, until its entry is retired. Counting stays exact (count-time predicate on the imported session), so a link visible in another repo costs context but never a counter.

#### 18.2.4 Batch mode (`run --harness codex`): plan, not built

Not built: the worker (`batch/worker.rs`), `Substrate::rollout_cmd` (returns `omp::ToolsCall`) and `run_rollout` (omp argv, `omp::verify_stream`) are omp-typed, and anchor replay reuses the omp binary; the change spans `run.rs`, `rollout.rs`, `substrate.rs`, `worker.rs`. The exact plan:

1. `RunArgs.harness: omp|codex` (default omp), carried in the job payload; `Substrate::rollout_cmd` returns `(program, argv, env)`; `OmpSubstrate` keeps today's argv.
2. `CodexSubstrate::materialize`: `git worktree add --detach <variant>/wt HEAD` as today; the effective tree written to `<variant>/wt/.agents/skills/<name>/` (repo scope, so only this rollout sees it) with `.agents/` appended to `<wt>/.git/info/exclude` (the worktree's `info/exclude` path from `git rev-parse --git-path info/exclude`) so verifiers diffing the worktree never see it; `HOME=<variant>/home` (empty, so `~/.agents/skills` contributes nothing) and `CODEX_HOME` left as is (auth lives there; its `skills/` and bundled system skills stay visible and are listed in the receipt as uncontrolled).
3. argv: `codex exec --json --ephemeral --cd <wt> --sandbox workspace-write --ignore-user-config -m <model> -- <prompt>` with `<model>` = `rematch-solver` resolved for Codex (`--model` on `run`, else Codex's default; recorded, not verifiable); env `REMATCH=0`, `REMATCH_SEED`; bound = task cap + 60 s through `proc::run_bounded` (codex has no `--max-time`).
4. Stream check (replacing `omp::verify_stream`): every non-empty line JSON, exactly one `thread.started`, ≥ 1 `turn.completed`, no `turn.failed` or `error` event; otherwise the rollout is invalid (verdict Fail "rollout invalid" without running the verifier), a time-capped run is still judged.
5. Trajectory: `import_codex::parse_session(stdout)` + `trace_records_of` (unit-tested on an `exec --json` stream), worktree path rewritten to the repo, `loaded_entries` = the materialized tree's ids, model = the `-m` value.
6. Verifier, receipts, next-run rule and anchor replay unchanged (anchor replay runs with the harness of the run that triggered it).

## 19. The lake (ADR 001)

History becomes a queryable backend: an append-only **journal** in the ledger records every write (`sessions`, `redirects`, `entries`, `counters`, `proposals`, `receipts`, `outcomes`) with the ledger's own clock as `known`; `rematch lake export` writes the journal to Parquet under `REMATCH_ROOT/lake/<table>/` (one Bellwether root per table, per-run files, never rewritten); `rematch lake index` builds Bellwether indexes under `REMATCH_ROOT/lake-index/<table>/` (per machine, never synced); `rematch lake query` plans through Bellwether and evaluates the residual in rematch. The hot path never reads the lake. Keys are declared only for questions a current reader asks (`report`, `why --asof`, `create --from sessions`, `improve`, `transfer suggest`); the rest of Bellwether's kinds are declined by name in the ADR with the question that would justify each. Identity that survives machines: `repo_remote` + subpath on predicates, `content_sha256` on entries, versioned `loaded_entries` (L1, built: journal and `meta` in §13, trace fields in §3, place matching and `content_sha256` in §6; `rematch lake migrate` fills them on rows written before them: `content_sha256` on every entry lacking it, `repo_remote`/`subpath` on predicates whose repo glob names a worktree on this machine (the glob stays) and on sessions whose repo exists here; idempotent, file reads only). Full design, key table, bitemporal semantics, build plan L1–L4 and the review record: `docs/adr/001-lake.md`.

### 19.1 Lake files and commands (L2, `crates/rematch-lake`, `crates/rematch/src/lake_cmd.rs`)

Built behind the cargo feature `lake` of the `rematch` package (default on; `arrow`/`parquet` 59.3, the versions Bellwether pins; snappy pages). `cargo build --no-default-features` builds the binary without arrow. Nothing in a session reads or writes the lake: `match`, `skills sync`, `trace-event`, `hook-check` never open it (`match` ≤ 50 ms release, test bound 100 ms on the debug binary).

```
lake/manifest.json                                   {lake_version: 1, bellwether_version_pinned: null until the first `lake index` (§19.2), watermarks: {machine: last exported journal seq}, events_exported: {session_id: true}, events_missing: [session_id]}
lake/events/{harness}/{day}/{session_id}.parquet     one file per closed session: its trace when traces/<id>.jsonl is closed (a session_shutdown record), else (imported history) the records `reflect --history` synthesizes from the harness transcript; harness omp | claude-code (cc:) | codex (codex:) | pi (pi:) | opencode (oc:); day = UTC date of session_start.t (a ledger-only session: started_at); the file name is `paths::encode_file_stem(session_id)` on every platform (`cc:<uuid>` → `cc%3A<uuid>`; `%`, `<>:"/\|?*`, control chars, a leading `.`, a trailing `.`/space and a Windows device name are `%XX`), so a lake copies between Unix and Windows unchanged
lake/{table}/{day}/{machine}-{seq}.parquet           sessions redirects entries counters proposals receipts: journal rows of one export run; day = export UTC day; seq = journal seq of the run's first row of that table (unpadded)
lake/outcomes/{domain}/{day}/{machine}-{seq}.parquet the same, split by subject.domain
lake/blobs/<sha256>                                  proposal replies and receipt certificates the exported rows point at
```

Files are written to `.<name>.tmp-<pid>` and renamed, never rewritten (an existing path is skipped) — with one exception: an `events` file exported before the `tool_cmd` column existed is rewritten once, by `lake index` (`events::upgrade`: the same records as a fresh export writes them now, so the bytes equal a new export's), because Bellwether reads one schema per root and refuses a key on a column some file lacks (`column "tool_cmd" not in source schema`); a scan before that derives the column from `tool`/`tool_input`. Partition values (`harness`, `day`, `session_id` of events; `day`; `domain` of outcomes) live only in the path. Time columns are `Timestamp(ms, "UTC")`, lists `List<Utf8>` (non-null items), statistics untruncated (`statistics_truncate_length(None)`, `column_index_truncate_length(None)`). Same journal rows ⇒ byte-identical files.

Events file names before the portable codec. Exports before it named a session's file by its raw id (`events/claude-code/<day>/cc:<uuid>.parquet`; `/`, `\` and NUL as `_`, a leading `.` prefixed `_`). Nothing is renamed or rewritten: such a file stays where it is and is still found (`events::find_events_file` tries the encoded name, then the raw one; Windows never holds a raw name with `:`), still settles its session (`lake export` writes no second file next to it), and reads back with the right `session_id` (`events::session_of_file` decodes only a stem that is exactly an encoding, so `cc:<uuid>` and a literal `a%41` stay as they are and nothing is decoded twice). `lake import` keys events by `(harness, decoded session_id)` and writes every copy under the encoded name, so a pre-codec Unix lake imports onto Windows and a session already present under either name is skipped. `session_id` in a Bellwether index of a pre-codec lake is the raw name for old files and the encoded one for new files; `lake query` rows carry the decoded id either way.

Columns. Every append table starts with `seq` (Int64, journal seq), `known` (ts, ledger clock of the write), `machine`, `op` (`insert`/`update`/`snapshot`), `row_key` and ends with `json` (the record as written, compact JSON):

| Table | Typed columns (between `row_key` and `json`) |
|---|---|
| `sessions` | `session_id`, `repo_remote`, `subpath`, `domain` (§6 "Domain"; null on rows written before it and in files exported before the column existed — the column is additive, readers take columns per file), `started_at` ts, `ended_at` ts, `family`, `loaded_entry_ids` list (the record's `loaded_entries`), `loaded_entry_shas` list, `visible_entries` list, `skill_reads` list, `exts` list, `stems` list, `redirects_json`, `flagged` bool, `counted` bool |
| `redirects` | `session_id`, `redirect_seq` Int64 (the redirect's trace seq; `seq` is the journal's), `prelabel`, `class`, `confidence` f64, `text_head`, `t` ts |
| `entries` | `entry_id`, `status`, `version` Int64, `content_sha256`, `predicate_hash`, `name`, `branch`, `valid` ts (`status_since`, else `created_at`) |
| `counters` | `entry_id`, `session_id`, `content_sha256`, `predicate_hash`, `family`, `matched`, `recurrence`, `harm`, `tokens`, `turns` (Int64), `ts` ts |
| `proposals` | `id`, `entry_id`, `session_id`, `blob`, `lint_ok` bool, `created_at` ts |
| `receipts` | `id`, `entry_id`, `certificate_hash`, `activation`, `created_at` ts |
| `outcomes` | `id`, `session_id`, `subject_id`, `signature`, `claim`, `facets` list (`domain=<each dotted prefix>`, `key=value`, bare `key`), `valid` ts (`ts`), `result_status` |

`events` columns: `seq` Int64, `t` ts, `ev`, `tool`, `call_id`, `tool_input` (JSON of `input`), `args_hash`, `result_bytes` Int64, `is_error` bool, `path`, `skill_read`, `text`, `prelabel`, `text_head`, `usage_json` (JSON of `usage`), `stop_reason`, `reasons` list, `flagged` bool, `extra` (JSON object of every other field of the record, nulls included; a field whose value does not fit its column's type goes here too; null when none), `tool_cmd` (derived, not a trace field: `input.command` of a `tool == "bash"` record, else null; every harness's shell tool is `bash` in the trace, §3; `events::read_records` never returns it).

Commands. `lake export [--all]`: journal rows with `seq` > this machine's watermark (rows of other machines, present only after a rebuild, are skipped), one run of ≤ 50 000 rows and ≤ 64 newly settled sessions, `--all` drains both; then the watermark moves to the last row of the run. Sessions go in session-id order: every closed trace file, then every ledger session without one, its records from `import_cmd::records_for_session` (the binary passes that converter to the lake crate as an `EventSource`); a ledger session with no transcript left is added to `events_missing` (it counts toward the 64, has no file, and is retried only by `--all`). `lake import --from <lake | REMATCH_ROOT>`: copies files whose `(table, machine, seq)` (events: `(harness, session_id)`) is absent, and absent blobs; watermarks merge by max per machine; `lake-index/` is outside every lake and never read. `lake rebuild [--from <lake>] [--force] [--machine <m>]`: replays one machine's rows (default: this machine's id) in `seq` order through `Ledger::apply_journal_row` into `ledger.sqlite.rebuild-<pid>`, copies the lake's blobs, then moves the result to `ledger.sqlite`; refuses a ledger holding any journal, entry or session row unless `--force` (the old file is kept as `ledger.sqlite.pre-rebuild-<ms>`). `lake doctor`: machine, `journal_max_seq`, watermark, `lag` = max seq − watermark, files per table, events, blobs, `events: exported N, missing M, pending P` (pending = ledger sessions in neither manifest set), orphans (temp files, names off the layout, files past their machine's watermark), the `op = snapshot` range (rows that predate the journal: state at migration, not transitions). Export, import and rebuild hold `REMATCH_ROOT/.lake.lock`.

### 19.2 Indexes and queries (L3, `crates/rematch-lake/src/{index,query}.rs`)

Bellwether is an external binary, optional and never linked: `--bellwether <path>`, else `$REMATCH_BELLWETHER`, else `bellwether` on `PATH`. Without it `lake index` fails naming the three, and `lake query` reads every file.

**`lake index [<table>…] [--repin] [--bellwether P]`** (holds `.lake.lock`; default all tables) runs, per table root with files, `bellwether index --json lake/<table> --index lake-index/<table> --path-template <T> --key <spec>…` (incremental: Bellwether reads only new or changed files). Every spec below was accepted as written by bellwether 0.1.0 and is the identity under which its manifest records completeness (`key_spec_completeness`; the temporal2 sidecar under its name):

| Table | `--path-template` | `--key` |
|---|---|---|
| `events` | `{harness}/{day:date}/{session_id}.parquet` | `exact:tool_cmd,counts`, `text:tool_cmd,tokenizer=words`, `exact:path`, `exact:skill_read` |
| `sessions` | `{day:date}/{machine}-{run_seq:int}.parquet` | `exact:repo_remote,counts`, `exact:domain`, `list:loaded_entry_shas`, `list:exts`, `list:stems`, `range:started_at` |
| `redirects` | the same | `temporal:session_id,redirect_seq@known`, `exact:class` |
| `entries` | the same | `temporal2:entry_id@valid,known` (a storage-version-1 sidecar), `exact:content_sha256` |
| `counters` | the same | `temporal:content_sha256@ts` |
| `proposals`, `receipts` | the same | `exact:entry_id` |
| `outcomes` | `{domain}/{day:date}/{machine}-{run_seq:int}.parquet` | `exact:signature`, `temporal2:subject_id@valid,known`, `list:facets` |

Adaptations, each forced by the binary: (1) the ADR's `{machine}-{seq:int}` placeholder is `{run_seq:int}`, because the files store `seq` per row and Bellwether refuses a placeholder whose stored column disagrees with the path: `row group 0 stores column seq and holds more than one value of it (its min and max differ), so it does not show the value its path gives (seq=5); a file whose path and content disagree, or whose statistics cannot show they agree, is refused`. `machine` is stored and in the path; one run file holds one machine, so they agree. (2) The ADR's `temporal:session_id,seq@known` names the stored `redirect_seq` (the journal's `seq` is another column). Path placeholders become row columns (`day` Date32, `run_seq` Int64, `harness`, `session_id`, `domain`, `machine` strings). Bellwether never lists a path component starting with `.` or `_` (an empty outcome domain is written as `_`): `lake index` reports such files as `unindexed_files`, and `lake query` on that table scans.

Version pin: the first index writes `bellwether --version` (`0.1.0`) to `lake/manifest.json` `bellwether_version_pinned`. Another version: `lake index` refuses (`the lake's indexes were built by bellwether A and this binary is B; run rematch lake index --repin …`), `lake query` scans with that reason, `lake doctor` reports it as `index_refused`. `--repin` deletes every `lake-index/<table>` and rebuilds all tables under the new version; the lake files are never touched.

**`lake query <table> --key K (--values v1,v2… | --has w1,w2…) [--from --to] [--valid V] [--known K] [--latest] [--all] [--limit n]`** (instants: ms UTC, RFC 3339, or `YYYY-MM-DD`); `rematch_lake::query::run(root, &QuerySpec, bin)` for readers. `K` is a key above by its spec or short name (`exact:tool_cmd`, `text:tool_cmd`, `exact:path`, `list:stems`, `temporal2:entry_id`, `temporal:content_sha256`, `temporal:session_id,redirect_seq` with values `sid:seq` or `sid\tseq`). A text key takes `--has` (every word required; each argument is split at Unicode word boundaries after case folding, `rematch_core::words`, the tokenizer Bellwether's `words` uses at the versions it pins — `unicase` 2.10.0, `unicode-segmentation` 1.13.3 — so `--has "cargo test"` = `--has cargo,test`; an argument with no word is a usage error); every other key takes `--values`, whose values go to a Parquet key file (`lake-index/.keys-<pid>-<n>.parquet`, deleted after) whose columns are the key's columns at the dataset's types (`list`: one Utf8 column named by the list column), then:

| Key kind | Request | Bellwether |
|---|---|---|
| `exact`, `temporal` | values [+ window] | `locate --keys F [--from --to --ts <window column>]` |
| `text` | words (`--has`) | one `locate --has <column>=<word>` per word (each answers `has_token` exactly at row-group grain: `exact_row_groups: true`); the planned row groups are intersected across words, every plan's residual applied; `--has` "cannot be used with --from/--to/--ts" (window applied by rematch); `plan.lookup` is then the list of lookups and `plan.planned` the intersection `{files, row_groups}` |
| `list` | values, `--all` or any | `locate --keys F --all` / `--any` (which "cannot be used with --from/--to/--ts"; window applied by rematch) |
| `temporal` | `--latest` / `--valid V` | `latest` / `asof --at V` |
| `temporal2` | `--latest [--known K]` / `--valid V --known K` | `latest --known K` (i64::MAX when absent; `latest` without it needs a `temporal` key) / `asof --valid V --known K` |
| `temporal2` | values only (every version) | none: the binary refuses `locate` on the sidecar's column ("none of the key specs … serves a lookup on [entry_id]"), so a scan |
| `range:started_at` | window only | none (`locate` needs keys), so a scan; it prunes `exact:repo_remote` windows |

A window is on the table's time column (`events` `t`, `sessions` `started_at`, `redirects` `known`, `entries`/`outcomes` `valid`, `counters` `ts`, `proposals`/`receipts` `created_at`), inclusive, and never combines with `--latest`/`--valid`/`--known`. The plan consumed is the `--json` line's `evidence.record.body.plan`: `entries[{file:{path (canonical), size, etag, tail_blake3}, row_groups:[in-file index…], bytes}]` and `residual`, a tagged tree (`{op: and, all:[…]}`) of `in {columns, values}`, `between {column, lo, hi}`, `not_older_than {columns, ts_column, bounds:[[key, ts]…]}`, `latest_per_key {columns, ts_column}`, `text {column, operator: has_token|contains|has_prefix, values}` (values as given, folded by the consumer), `contains_any {column, values}`, `contains_all {column, values:[[group…]…]}`, every other value a canonical encoding (Bellwether ADR 016) as a JSON byte array. rematch encodes each row's cells the same way (Utf8 `06 … 00 00`, Int64 `02` + sign-flipped big-endian, `Timestamp(ms)` `08 04 02` + Int64, Date32 `08 01 05` + Int64, Bool `01 b`, Float64 `04` + sign-aware flip) and compares bytes, so `between` is byte order. Observed shapes: `locate` on `exact` → `in`; `--has` → `text {operator: has_token, values: [word]}`; on `list` → `contains_any`/`contains_all`; `exact`/`temporal` + window → `and[in, between]`; `latest` → `and[in, not_older_than, latest_per_key]`; `asof --at` → `and[in, between, not_older_than, …]`; temporal2 → `and[in, between(valid), between(known), not_older_than(valid), not_older_than(known), latest_per_key(valid)]`. Any other `op` (`semi_join`, `join`, `window_partition`, `expr_in`) is refused naming it, never ignored. `latest_per_key` keeps every row at its key's greatest time (ties kept, as the plan keeps every row group at the winning time); a null time never wins. `text` folds the row's value and each argument (`has_token`: one of the value's words equals it; `has_prefix`: one starts with it; `contains`: a substring); a null never matches. The planned row groups are read with the parquet reader (`with_row_groups`) and rows sorted by (file path, row number in the file), so an indexed answer and a scan answer are the same list.

Scan (`indexed: false`, `reason` says why): no binary; no `lake-index/<table>/manifest.json`; a pinned version the binary does not match; files Bellwether does not list; a lookup no key serves (above). The scan reads every file of the table and applies the same predicate locally (`in`/`text`/`contains_*`, the window, and for `--latest`/`--valid`/`--known` per key: times ≤ the instants, then the greatest valid, then the greatest known at it). Before an indexed lookup, a table whose files the index does not track (new, resized, gone), or whose index was built before the key asked for was declared, is re-indexed (`reindexed: true`): the ADR's "when `lake query` finds a root with files newer than its manifest". `lake index` (and that re-index) first upgrades pre-`tool_cmd` events files (above; `upgraded: n` per table) and removes an index root whose manifest records a key the table no longer declares (an `expr:tool_cmd` index from before the stored column; Bellwether keeps every spec an index was built with and refuses an `expr` name equal to a dataset column), rebuilding it from scratch (`rebuilt: true`). Each Bellwether lookup also writes an evidence record under `lake-index/<table>/ledger/` (the index is per machine and rebuildable).

`lake doctor [--bellwether P]` adds `index`: the binary and its version against the pin (`index_refused`), per table whether it has an index, its untracked/gone/skipped files and each key's completeness, and `sessions_without_counters`: session ids whose newest `sessions` row is `counted` with loaded entries and that have no `counters` row anywhere in the lake (the attribution anti-join the ADR keeps out of the index).

### 19.3 Readers and `report` (L4, `crates/rematch/src/{lake_read,report}.rs`)

Historical readers read the lake when it exists (`lake/manifest.json` present, binary built with `lake`) and fall back to today's path otherwise or when the lake cannot be read; every one names its source in its envelope (`"source": "lake"|"ledger"`). Readers of journal tables also fall back while the lake **lags** this ledger (`ledger.journal_max_seq() > manifest.watermarks[machine]`, a line on stderr): an export lag never hides a local write. Rows from either side are journal rows (`JournalRow`: `machine`, `known`, `seq`, `row_key`, the record as `json`), read through `lake_read::rows` — the lake through `rematch_lake::query::run` with the key below (indexed, else the same rows by scan) or `query::scan`, the ledger from its own `journal` table — and deduped by `lake_read::as_of(rows, K)`: per `(machine, row_key)` the row with the greatest `known ≤ K`, ties by `seq` (ADR 001 §"Bitemporal semantics"). A lookup only narrows the lake's rows; each reader applies its own filter to either side.

| Reader | Today's path (fallback) | With the lake | Envelope |
|---|---|---|---|
| `reflect --history` | `import_cmd::read_transcript` (subagent from the transcript) | `events/<harness>/<day of started_at>/<sid>.parquet` by path, `events::read_records` → trace records; subagent = `session_start.agent.kind == "sub"`; per session, a missing or unreadable file falls back | `history.source` (`lake` when any session came from it), `history.sources {lake, ledger}` |
| `improve` excerpt + clusters | `import_cmd::records_for_session` (trace, else transcript) | the same events file first (`import_cmd::session_records`) | `source`, `sources` |
| `create --from sessions` reference search | every ledger session | `sessions` `list:stems` ∪ `list:exts` contains_any (every machine), latest row per session, `started_at` order, then the same overlap scoring; reference excerpts from the events file, else the trace | `source`; the "found N matching session(s)" refusal names it |
| `transfer suggest` facet keys | `outcome_facets` ⋈ `outcomes` | `outcomes` latest row per outcome (every machine): `facets[].key` per branch (the bare keys of `list:facets`) | `source` (the session-start digest's suggestions stay on the ledger: it never reads the lake) |
| `library why <sid> --asof <ts>` | the ledger's `journal` (`entries` by entry id, `redirects` by `<sid>#<seq>`) | `entries` `temporal2:entry_id` + `redirects` `temporal:session_id,redirect_seq` (every version, then `as_of`) | `source`, `asof {ts, utc}`, per loaded entry `asof {status, version, content_sha256}` (null: not written yet), per redirect `asof {recorded, class}` |
| `report` | the ledger's `journal` | `entries`, `counters`, `redirects` by scan, `sessions` `range:started_at` over the window; the lake alone, at any lag (reported) | `source`, `lake_lag` |
| `tune` (and the pass inside `count`) | the ledger's `journal` (`sessions`, each its latest row) | `sessions` `range:started_at` over the window, only while the lake holds every journal row of this ledger (inside `count` the lake always lags, so the ledger); a session's `retrieval` records from its events file, else its trace | `source` (also in each proposal's `evidence.source`) |

`--asof` takes ms, RFC 3339, `YYYY-MM-DDTHH:MM[:SS]` (UTC) or `YYYY-MM-DD` (00:00 UTC); without it `why` is unchanged (`"source": "ledger"`). `library why` reads only this machine's rows (a ledger session's entries are this machine's ids).

**`report [--window 6w] [--since YYYY-MM-DD]`** (`<n>w|d|h`; window `[now − window, now]`, or `[since 00:00 UTC, now]`): every table as of the window's end `K = now`; redirect labels are the `redirects` rows as of `K` over the session row's redirects.

1. *Kept over ≥ 4.* Each entry whose status at `K` is `kept`: the distinct sessions of counter rows with `ts` in the window and `matched > 0` that are its own (`machine` and `entry_id`) or carry its `content_sha256` (any machine); `reached` = ≥ `KEEP_MIN_MATCHED` (4); recurrence and harm summed over those rows.
2. *Recurrence per trigger.* Non-draft entries grouped by `predicate_hash`, except a predicate tune's sibling (`Entry.tune`, §6 "Predicate tuning"), which joins the group of the entry its lineage started from; the trigger's predicate is that of its latest-updated entry, its class the first non-`none` `redirect_class` by `created_at` (none: correction or preference, `counters::class_recurs`, the rule `recurred` uses). A session started in the window is in the *with* arm when it loaded a member of the trigger (on the member's own machine by `loaded_entries` id — a tune sibling shares its parent's `content_sha256`, so only the id tells the versions apart —, on another machine by `loaded_entry_shas`) and the predicate *of a member it loaded* hits (`count_match(predicate, Place::of_session, exts, stems)`), so a widened sibling never counts a session against the parent's predicate and vice versa; it is in the *before* arm when it loaded none and the trigger's predicate hits. Per arm: `sessions`, `recurred` (sessions with ≥ 1 redirect of the class), `redirects` (their count), `rate = recurred / sessions` (null on no session); `delta = with − before`; `covered` = with-arm non-empty; `fell` = `delta < 0`.
3. *Predicate tunes.* Every entry whose `tune.at` falls in the window, with its parent: the parent's with-arm (sessions that loaded the parent and its predicate hit), the sibling's with-arm (loaded the sibling, its predicate hit) and the before-arm of the parent's predicate (loaded neither), side by side, so a widening is read against the version each session loaded. JSON `tunes [{machine, name, at, direction, parent {id, version, status, predicate_hash, predicate}, tune {…}, added, removed, added_exts, domain_set, evidence, redirect_class, v1, v2, before}]`.
4. *Verdict*: `verdict: an entry reached kept over ≥ 4 matched sessions: yes (<names>)|no; recurrence fell on a covered trigger: yes (<triggers>)|no`; built-in entries (`library::is_builtin`, every entry of the trigger) are listed (`(built-in)`) and never count. JSON `verdict {kept_over_min, kept_entries, recurrence_fell, fell_on}`.

Text lines: a header (`source`, lag, machines, window), one `kept …` line per kept entry (or `kept: none`), then per trigger domain (the trigger predicate's `domain`, `(none)` without one; domains in name order, only those with a matched session) a summary `domain <d>: <n> trigger(s), <c> covered, <f> fell · with … · before …` (arms summed over its triggers: a session matching two triggers counts twice) followed by its indented `  trigger …` lines, one per trigger with a matched session (`with i/n recurred (r redirect(s), rate x) · before …[ · Δ d[ fell]]`), one `tune <name> v<a>→v<b> (<at>, <status>): <note> · v<a> with … · v<b> with … · before …` line per tune, the verdict. JSON: each trigger carries `domain`; `domains [{domain, triggers, covered, fell, with, before}]`.

## 20. Profile (`rematch_core::profile`, `crates/rematch/src/profile_cmd.rs`)

One person's omp setup — what the loop kept, what they wrote by hand, what they approved and configured — as a git working tree at `REMATCH_ROOT/profile/`, synced across machines through any git remote. omp formats only (no renderers for other harnesses); everything is linked into the places omp and rematch already read, so neither needs to know the profile exists.

```
profile/
  skills/<name>/              kept skill entries (the keep writes here) and adopted hand-written skills; <agent_dir>/skills/<name> → here
  agents/<name>.md            kept agents' AGENT.md copies and adopted hand-written agents; <agent_dir>/agents/<name>.md → here
  fragments/<name>.md         AGENTS.fragment.md of kept entries whose dir is not under skills/ (kept agents)
  hooks/<id>.ts               approved compiled hooks; <agent_dir>/extensions/rematch-hooks/<id>.ts → here
  config/policy.json          REMATCH_ROOT/policy.json → here
  config/roles.yml            {<role>: <selector> | {default: <selector>, <hostname>: <selector>}}
  config/domains/<branch>.yml REMATCH_ROOT/branches/<branch>/domain.yml → here
  improver/<file>             improver files the user edited (hash ≠ improver/.shipped/<file>); improver/<file> → here
  profile.json                {"version": 1, "machines": [hostname…]}
  .gitignore                  .conflicts, skills/*/rematch.json, skills/*/EXPERIENCE.md, temp files
  .conflicts                  paths the last sync could not rebase (per machine, ignored)
  .index.json                 per skills/<name>: {machine, at, commit} of the last commit touching it (`git log -1 --format=%s -- skills/<name>` = "<machine> <ts>"), written by every sync (per machine, ignored)
```

**Per machine, never in the profile:** the ledger and its journal, the lake and its indexes, `staging/` (provisional entries), `drafts/`, `archive/`, `predecessors/`, traces, pending files, jobs, credentials and omp's own config (concrete model selectors only through `roles.yml`), and inside `skills/<name>/` the ledger mirror `rematch.json` (absolute paths, this ledger's state) and the reflector's `EXPERIENCE.md`. History is the lake's (§19), not the profile's.

**Present** = `profile/.git` exists. Without it nothing changes anywhere.

**Keep path.** `library::dir_for(kept|pinned)` of a non-agent entry is `profile/skills/<name>/`; `transition` links `<agent_dir>/skills/<name>` → it after a keep and removes that link when the entry leaves kept (only while it points at the entry's dir). `promote_into` treats what holds `<agent_dir>/skills/<name>` (a dir kept before the profile, a user's skill or a foreign link) as the replaced occupant (`predecessors/<name>/<version>/`); `rollback` restores into the profile and relinks. Kept agents keep their entry dir in `kept-agents/<name>/`; `write_kept_agent` copies `AGENT.md` to `profile/agents/<name>.md` and links `<agent_dir>/agents/<name>.md` to it (`remove_kept_agent` removes both). `approve` of a hook writes `profile/hooks/<id>.ts` and links `rematch-hooks/<id>.ts`; `remove_hook` removes both. `scope::anchor` finds the replaced kept entry at either location (`library::is_kept_slot`).

A keep whose name the profile already holds from another machine (a dir without this ledger's `rematch.json`) replaces it like any occupant: the other machine's version is saved as this machine's predecessor version 0, and the next sync carries the new version to every machine (last keep wins; `rollback` here restores it).

**Kept sources.** `library::sync_shared_skills` adds every `profile/skills/<name>/` with a `SKILL.md` (`profile::kept_sources`) to `REMATCH_ROOT/skills/` for names no ledger entry holds, so entries kept on another machine and adopted skills load like this machine's kept entries. They are files, not ledger entries, on machines that did not keep them: they load but are counted only by the machine whose ledger holds the entry, and a hook linked from another machine runs only where its entry is known (built-in entries have per-machine ids and are approved per machine).

**Profile-kept.** `profile_cmd::profile_kept`: the kept sources no entry of this ledger holds (no entry's `path` is the dir) — kept or adopted on another machine. `library ls` lists each after the entries as `kept (profile, from <machine>) skill  <name> [profile] not counted on this machine` (JSON `profile_kept [{name, status: kept, source: profile, from, path, counted: false}]`), `library why` as `kept (profile, from <machine>) <name>: linked into the shared skills dir, not counted on this machine[ · read in this session]` (`profile_kept[].read` from the session's `skill_reads`), and `report` (which already excludes them: they have no counters here) adds one line after its header, `profile-kept (not counted on this machine): N` (JSON `profile_kept`). The machine comes from `.index.json`, else (a name the last sync did not see) from the same `git log`; `unknown` without either.

**omp only.** `profile adopt` refuses another harness's files with `<path> is <why>: the profile holds omp skills and agents only (a dir with SKILL.md, an agent .md); CLAUDE.md, settings and other harnesses' files stay out`: anything under Claude Code's config dir (`$CLAUDE_CONFIG_DIR`, else `~/.claude`) or Codex's (`$CODEX_HOME`, else `~/.codex`; `~/.agents`), inside any `.claude`/`.codex`/`.agents` dir, and `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `settings.json`, `settings.local.json` anywhere; paths under the omp agent dir are always accepted. Claude Code and Codex reach the same skills through `REMATCH_ROOT/skills` (§16), never through the profile.

**Commands.**

| Command | Behavior |
| --- | --- |
| `profile init [--remote <url>] [--adopt] [--timeout 10]` | `git clone <url>` (bounded; an empty remote or one whose HEAD names a missing branch checks out `main`, else `master`, else its first branch, else starts `main`) or `git init` on `main`; an existing profile only gains `origin` when it has none. Then the layout and `.gitignore` lines, `--adopt`, and one `sync`. `--adopt`: each kept/pinned entry rematch owns moves into the profile (`library::adopt_kept`: the dir with its ledger path and `rematch.json`, or the kept agent's copy), then every remaining real dir in `<agent_dir>/skills/` with a `SKILL.md` and every regular `<agent_dir>/agents/*.md` whose `rematch:` block names no entry of this ledger is adopted as below. |
| `profile adopt <path>` | A skill dir (with `SKILL.md`) moves to `profile/skills/<name>/`, an agent file to `profile/agents/<name>.md`; a link takes its place. A kept entry rematch owns moves as with `--adopt`; a skill registered before keeps its entry with the new path; any other skill is registered (`improve::register`, branch `shared`) as a **pinned** entry (status and flag, origin `import:profile`): measured, never moved or replaced by the loop. Refused for a link, a name the profile holds, an invalid name. Then the views. |
| `profile sync [--no-push] [--timeout 10]` | Under `REMATCH_ROOT/.profile.lock` (another sync running ⇒ `skipped`; a lock older than 5 min is taken over): `collect` (a regular `policy.json`, `branches/*/domain.yml`, edited improver files and hooks approved before the profile move in, links left; a name the profile already holds stays local, `kept_local`), fragments, `profile.json` machines, `git add -A` + commit `"<hostname> <UTC ts>"` when dirty; with `origin`: `git fetch` then `git rebase origin/<branch>` (no autostash; the tree is committed). A rebase that stops on conflicts is aborted — the tree is back at the local commit, clean — and the paths are returned as `conflicts` and written to `profile/.conflicts` (cleared by the next sync that rebases cleanly; kept while offline). Then the views (`profile::link_views`) and the shared skills dir, then `git push origin HEAD:refs/heads/<branch>` when ahead and nothing conflicted. Fetch and push share `--timeout` seconds (each at least 1 s); a failure or timeout is `offline: true` with `error`, never a failed command. Returns `{machine, branch, remote, committed, pulled, pushed, offline, error, conflicts, collected {moved, kept_local}, fragments, views {linked, pruned, untouched}, skills {added, pruned, total}, elapsed_ms, lines}`. |
| `profile status` | No network: `{present, dir, machine, branch, remote, head, ahead, behind (against the last fetched origin/<branch>), dirty, conflicts, machines, skills, agents, hooks, roles (this machine's roles.yml selectors), lines}`. |
| `profile install-launchd [--interval 300]` | Writes `~/Library/LaunchAgents/com.vncp.rematch.profile-sync.plist` running `<rematch> profile sync` (a full sync: pull and push) every `interval` seconds and at load, with `HOME` and the set ones of `PATH`, `REMATCH_ROOT`, `PI_CONFIG_DIR`, `PI_CODING_AGENT_DIR`, `OMP_PROFILE`, `PI_PROFILE`, `REMATCH_MACHINE`, output to `REMATCH_ROOT/profile-sync.log`; the binary is `~/.local/bin/rematch` when it exists, else the running one. Prints `launchctl load -w <plist>`; never loads it. |

**Views** (`profile::link_views`, idempotent). Each profile item is linked where its reader looks: created when absent, re-pointed when it is a link into the profile or dangling; a real file or dir, or a link elsewhere, is the user's and stays (`untouched`). A link whose profile target is gone is pruned. An improver file that still equals its `.shipped` hash gives way to the profile's edited copy; a local edit stays. `install_improver` then sees the link's content as the user's edit (its hash differs from the shipped record) and leaves it.

**Roles.** `config::resolve_chain` asks `profile::role_selector` for each role of the chain before `config.yml`: key = the role or the role without `rematch-` (`editor` = `rematch-editor`), value a selector or `{default, <hostname>}` (hostname = `$REMATCH_MACHINE`, else `gethostname`); `doctor` reports `via profile:<role>`.

**Session start** (§10): the extension runs `profile sync --timeout 8` in the background once per process, only when `match` reported `profile_present`. **Digest**: one `profile: N conflict(s) not synced (<paths>); resolve with git -C <profile> pull --rebase, then rematch profile sync` line while `.conflicts` lists any. **Uninstall** leaves `profile/` (the user's repo) in place and removes every other child of the root, the links into the profile (`<agent_dir>/skills/<name>`, `<agent_dir>/agents/<name>.md`, `rematch-hooks/`, `policy.json`, `domain.yml`, improver links) and the launchd plist; an adopted hand-written skill or agent (no `rematch:` block) is restored as a copy where its link was.
