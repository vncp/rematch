An entry is one item of the library: a skill, rule, script, agent, hook, fact or lesson, with its own trigger, counters and status. Its status decides where it lives and whether it loads.

	name="lifecycle"

Kept becomes stale when a fact source, the model family or the fork commit changed, or retired at two harm events in thirty days. Stale returns as a new canary or retires. Retired never leaves. ## Statuses

| Status | Lives in | Loads |
|---|---|---|
| `draft` | `~/.rematch/drafts/<name>/` | never |
| `provisional` | `~/.rematch/staging/<branch>/<name>/` | in the view of places whose predicate matches |
| `kept` | `~/.omp/agent/skills/<name>/` (agents: `~/.omp/agent/agents/<name>.md`) | natively and through `~/.rematch/skills/` |
| `stale` · `dormant` · `retired` | `~/.rematch/archive/<status>/<id>/` | never; never deleted |
| `pinned` | wherever it is | a flag: never replaced automatically |

- **Pinned** is a flag (`retention: user_decision`), not a place. Automatic transitions refuse pinned entries; `disable` and `rollback` are your actions and proceed.
- **A kept entry replaced by a sibling becomes dormant**, not retired, with its files in `predecessors/<name>/<version>/`. `rollback` must be able to restore it, and retired never leaves.
- **Declining an entry's executable/agent approval (`<entry-id>`) retires the entry;** declining its personal instructions (`instructions:<entry-id>`) declines only the prompt text and keeps the entry.
- **Every kept entry keeps its predecessor**, so `rollback` always has something to restore ([D13](/rematch/background/decisions/)).

When each transition fires: [counters and the kill criterion](/rematch/concepts/counters/). Files inside an entry: [entry layout](/rematch/reference/entry-layout/).

## Where skills load from (scoped exposure)

Storage is shared, while provisional exposure is scoped per place so one repo's trials never leak into another's sessions ([D30](/rematch/background/decisions/)):

| Directory | Holds | Target |
|---|---|---|
| `~/.rematch/skills/` | **kept library only** (kept/pinned entries + `profile/skills/<name>/` kept sources; never unpinned provisional trials, never a name with a [place scope](/rematch/concepts/predicates-and-domains/#place-scopes)) | `~/.omp/agent/skills/<name>/` or `profile/skills/<name>/` |
| `~/.rematch/views/<key>/skills/` | per-place view (`<branch>-<16hex sha256(path, remote, subpath, domain)>`): kept library links + kept skills scoped to that place + provisional entries matching that place (shadowing a kept entry of the same name in that view only) | `staging/<branch>/<name>/` or the kept dir |
| `~/.rematch/views/<key>/trials/` | what only a repo's top level gets: provisional entries matching it and kept skills scoped to it | `staging/<branch>/<name>/` or the kept dir |

| Harness | Reads kept + provisional trials through | Synced by |
|---|---|---|
| **omp** | runtime override of `skills.customDirectories` (user dirs minus any rematch dir + this place's `views/<key>/skills`, replaced on cwd/session change) | the extension, at omp start and on cwd/session change |
| **Pi** | `resources_discover` returning this place's `views/<key>/skills` | the Pi adapter, at session start |
| **OpenCode** | config hook setting this process directory's `views/<key>/skills` in in-memory `skills.paths` | the OpenCode plugin |
| **Claude Code** | plugin `skills/ → ~/.rematch/skills` (kept library) + `SessionStart` `additionalContext` listing this place's provisional skills (`"Skills on trial in this repo…"`) and kept skills scoped to it (`"Skills of this repo (scoped here…"`), with `<view>/skills/<name>/SKILL.md` paths | the plugin's `SessionStart` hook |
| **Codex** | `~/.agents/skills/rematch → ~/.rematch/skills` (kept library) + git-excluded repo link `<repo>/.agents/skills/rematch-trials → ~/.rematch/views/<repo-top-key>/trials` | `rematch skills sync --harness codex --cwd "$PWD"` |

- **No cross-repo trial leakage.** Each place writes only its own view under `~/.rematch/views/<key>/`; concurrent sessions in other repos never touch it and nothing global is pruned per cwd.
- **Status changes apply at once.** Keeping re-points the link; retiring, archiving or disabling prunes dead links from `~/.rematch/skills/` and every view; `rematch off` empties `~/.rematch/skills/`, all `views/*` and `~/.rematch/agents/`, removes every repo-local item in `project-links.json`, and takes the unchanged rematch blocks out of `<agent_dir>/AGENTS.md`.
- **Every omp profile shares `~/.rematch`**, so a skill kept under one profile loads across profiles and harnesses. Personal instruction blocks are the exception: each omp profile has its own `<agent_dir>/AGENTS.md`, and an approval in one never writes another's (the [profile](/rematch/concepts/profile/) can carry them across).
- `rematch skills sync --cwd <dir>` syncs by hand and prints the view's links, agent exposure, and the always-on catalog vs on-demand body byte report.

## Subagents

When the fix for a correction is "read this big thing and report the one line that matters" (a build log, a long diff, a data dump), the editor may propose a subagent (`kind: agent`) instead of a skill. It runs in its own context and returns text, so the big input never enters your session.

An `AGENT.md` holds `name`, `description` (what the main agent sees when deciding to delegate), optionally `model`, and a body that is the subagent's system prompt.

| Status | Where | Seen |
|---|---|---|
| provisional, **approved** | `staging/<branch>/<name>/`, linked from `~/.rematch/agents/<name>.md` | in **omp** only where its place matches (other places hide it per process via `task.disabledAgents`; fail-safe hides all rematch agents on error or `off`); in **Claude Code** via a git-excluded copy `<repo>/.claude/agents/<name>.md` in matching git repos |
| provisional, not approved | `staging/<branch>/<name>/` only | never: linked and copied nowhere until you approve `<entry-id>` |
| kept (`accepted_in_use`, after 4 clean completed sessions that invoked it) | `~/.rematch/kept-agents/<name>/`, copied to `~/.omp/agent/agents/<name>.md` (and `<claude-plugin>/agents/<name>.md`) | natively in omp and Claude Code |
| retired · dormant · stale | link or copies removed; entry archived | never |

- Approval is bound to `AGENT.md` without its `rematch:` block: editing the body asks again.
- A native user (`<agent_dir>/agents/*.md`) or project (`.omp/agents/*.md` / `.claude/agents/*.md`) agent of the same name **shadows** the provisional candidate: rematch never disables your native agent by name, and the candidate is neither offered nor credited.
- `/rematch off` (and `library disable <id>`) immediately removes `~/.rematch/agents/` links, withdraws `<repo>/.claude/agents/<name>.md` copies (tracked in `~/.rematch/project-links.json`), and disables rematch agents for the running omp process. Pi, OpenCode and Codex do not load subagent entries.
