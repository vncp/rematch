A session that ended with a correction produces at most one bounded proposal at the start of the next session. Later sessions that match expose it through that place's view, and engine-owned evidence—sustained clean actual use or an authorized comparative probe—decides whether it stays. Interactive reflection never reruns your active session and uses at most three editor/classifier calls.

Inside a session, the extension only records and loads. Everything that proposes or decides runs in the binary, outside the session's model loop: started detached at the next session start, alongside your work. The line between them: [the evidence boundary](/rematch/concepts/evidence-boundary/).

## How a reflection works

<Steps>

1. **Flag.** At shutdown the session is flagged only if it carried a signal: a pre-labelled redirect (`interrupt`, `revert`, `negation`, `reprompt`), three tool errors in any six consecutive results, or `/rematch mark`. Clean sessions produce nothing.
   - Enforced by the extension, within a 2-second budget, so it writes one small file.

2. **Classify.** One batched call labels each redirect `correction`, `preference`, `scope` or `none`. A session whose only redirects are `scope` or `none` gets no editor call. A mark overrides the classifier.
   - `reflect.rs`

3. **Triage.** The first failure is *process* (anything the agent produced with tools, error clusters, takeovers, reverts, procedural text) or *content* (a corrected prose answer). Content failures are logged, not proposed on. The scope picks the editor: *domain* by default, *invariant* when the failure is about the agent's general way of working.
   - `trace::triage`

4. **Predicate.** The trigger: repo, the extensions of files touched in the evidence window, and up to ten stems from the task turn, the touched files and the redirect. Its hash keys the rate limits. Details: [predicates](/rematch/concepts/predicates-and-domains/).
   - `predicate::derive`

5. **Propose.** One editor session through `omp -p --no-tools`, given the trace excerpt, the deliverable, the redirect, the current entry if any, and matching lessons. The prompt treats the trace as data. The reply is edits plus a manifest: evidence moment, predicted fix, predicted regression. `KEEP_BASE` is a valid answer.
   - `improver/editor.md`; `omp.rs` verifies provider and model on every event

6. **Lint.** Static and free: every rule in `improver/lint.toml`. On an error the editor gets one retry with the findings. Rules: [lint](/rematch/reference/lint/).
   - `lint::lint_entry`

7. **Stage.** Written to `staging/<branch>/<name>/` as provisional, with the predicate, model family, originating session and manifest. A near-duplicate routes its evidence to the existing entry instead.
   - `library::stage`, `dedup`

8. **Load (scoped per place).** At the next session start, `skills sync` links the kept library (`~/.rematch/skills/`) plus only the provisional entries matching that place into `~/.rematch/views/<key>/skills/`. There is no withheld arm, and another repo's trials are never exposed here.
   - `library::sync_shared_skills`, `library::sync_view`, `library::list_for_match`

9. **Count, probe and decide.** For every finished trace: did the session complete and actually use the entry (`used`), did the motivating redirect class recur (`recurrence`), and was there `harm`? If an eligible provisional entry has an authorized replay task, `reflect --pending` can also run one bounded omp comparison (2 rollouts, ≤ 300 s each, 1 per pass, 4 per 24 h). After a keep or retire, the reflector writes `EXPERIENCE.md` beside the entry.
   - `counters::fold_session`, `probes::pass`, `counters::decide` — rules: [counters](/rematch/concepts/counters/) and [automatic probes](/rematch/guides/automatic-probes/)
</Steps>

## Why it is built this way

| Choice | Why | Decision |
|---|---|---|
| No proposal without a trace | every entry cites the moment (`session_id`, `seq`) it came from; editing a harness without an execution behind it dropped Harness² from 73.4 to 63.2 on code | D1 |
| At most three editor/classifier calls | one batched classifier call, one editor, one lint retry; optional background probes run only on tasks you explicitly authorized (2 omp rollouts, 0 editor calls) | D6, D7, D31 |
| No composer and no model selector in interactive mode | choosing between untested texts is blind selection, which produced Harness²'s worst regressions | D6 |
| Kept by actual use or comparative support, judged by recurrence | catalog listing alone earns no credit; keep requires ≥ 4 clean completed sessions with actual use (`accepted_in_use`) or a bound supporting comparison (`comparative_support`); unvalidated patches were net negative in Harness-R1 (21 of 39 lowered success) | D8, D10, D31 |
| Appended, never rewritten | entries are itemized units with their own counters; a model never rewrites the library or the improver prompts; a monolithic rewrite collapsed a context from 18,282 tokens to 122 in ACE | D14, D25 |
| Only failures are reflected on | the system never grades its own successes | D9 |
| Modest expectations | published harness gains were 54% overfitting on audit; the deployed-static regime showed low single digits for strong models | D18, D19 |

Evidence for each id: [research decisions](/rematch/background/decisions/).

## Models

- The editor is the strongest configured model; the classifier a fast one. There is no judge role.
- A reply from a different provider than configured is a failed run, never a fallback.
- Every entry records the model family it was created under, with a per-family breakdown of its counters. Entries load regardless of family, because gating would make them flicker as you switch models.
- When counters diverge (harm on one family, clean on another), the entry is split and the harmed family gets its own sibling.
- A family whose recurrence or harm rises across several entries appears as a review list in the digest, never as automatic retirements.

## Compared with other ways to improve a harness

| | Hand-written skills | compound-forge (SkillOpt / GEPA) | rematch |
|---|---|---|---|
| Evidence | your memory of what went wrong | a benchmark suite you maintain | the trace of the session that went wrong |
| Cost per improvement | your time | dozens to hundreds of rollouts | ≤ 3 editor/classifier calls; optional 2-rollout probe when authorized; 4–10 rollouts in batch mode |
| What decides | you | validation score on held-out cases | ≥ 4 clean actual uses (`accepted_in_use`) or an authorized probe (`comparative_support`), with 0 recurrence/harm |
| Activates on its own | everything you write | nothing (proposals are reviewed) | scoped skill/rule/fact trials; never personal `AGENTS.md`, scripts, hooks, agents, probes, team or fork changes |
| Exit for a bad change | you notice | regression on the suite | counters or a regressed probe retire it; rollback restores the predecessor; `off` stops everything |

The loop design, scoped editors, lint for generalization and the experience library come from Harness² (Xu et al., arXiv 2610.14224); the `improver/` prompts are derived from its Appendix H, not verbatim. rematch adds personal-first harness optimization with scoped trials (D29, D30), dual retention evidence (`accepted_in_use` and `comparative_support`, D10, D12, D31), and a persistent action queue that keeps executable and prompt changes behind explicit approval (D24, D32).

<Aside type="note" title="Observational acceptance vs comparative support">
Sustained clean use in real sessions is positive evidence of acceptance, not a controlled causal proof of improvement. A bounded probe compares baseline and candidate on one authorized task, seed and model in omp—not universal correctness. Nothing is ever called verified.
</Aside>
