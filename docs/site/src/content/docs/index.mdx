## Install

<Tabs syncKey="harness">
<TabItem label="omp">
```sh
scripts/install.sh
rematch doctor --text    # ready: true
```
</TabItem>
<TabItem label="Claude Code">
```sh
cargo build --release
ln -s /path/to/rematch/adapters/claude-code ~/.claude/skills/rematch
```
</TabItem>
<TabItem label="Pi">
```sh
cargo build --release
pi install "$PWD/adapters/pi"
```
Pi 1.4.x, from a Rematch checkout.
</TabItem>
<TabItem label="OpenCode">
Add the checkout path to OpenCode's `plugin` array:
```json
{ "plugin": ["/path/to/rematch/adapters/opencode"] }
```
Build Rematch first. Tested with OpenCode 1.19.4.
</TabItem>
<TabItem label="Codex">
```sh
ln -s ~/.rematch/skills ~/.agents/skills/rematch
rematch skills sync --harness codex --cwd "$PWD"
```
Run the sync before starting Codex in a repo.
</TabItem>
</Tabs>

The live adapters trace while you work; Codex uses post-hoc import. Reflection uses omp with model access. See [installation and requirements](/rematch/start/install/) before starting.

## What you can do with it (and how)

| Goal | What you do | What rematch does |
|---|---|---|
| **Stop repeating the same correction** | Correct the agent in chat (*"no, …"*, *"revert that"*, or interrupt it) when it gets a workflow wrong. | At the next session start, a detached background reflection proposes a scoped skill, rule, fact, hook, subagent or personal instruction; low-risk entries start as a scoped trial in that repo only. |
| **Catch compiler/linter errors and broken callers right after an edit** | Nothing to configure (`fast-check` built-in hook). | After file edits, rematch runs the repo's fast check (`cargo check`, `tsc`, `ruff`/`pyright`/`mypy`, `go vet` + `go build`) plus `git grep` for changed signatures in unedited files, and injects one `◆ rematch · fast-check` card before the next turn. |
| **Create and test a new skill from scratch** | Ask your agent in chat: *"Create a rematch skill for `<task>` and eval it"* (or run `/rematch create` + `/rematch eval`). | Drafts or distills the skill package (`SKILL.md` + `units/` + `scripts/` + `evals/evals.json`), checks trigger & unit retrieval (`eval trigger`), runs baseline vs. with-skill rollouts (`eval run --activate`), writes `~/.rematch/evals/<name>/report.html`, and promotes the draft only if it passes the gate. |
| **Improve or split a bloated skill** | Ask your agent *"Improve the `<name>` skill with rematch"* or run `/rematch improve <name>`. | Audits the sessions that used the skill, mechanically splits > 8 KB `SKILL.md` files into `SKILL.md` + `units/` + `facts/`, or proposes unit-level fixes from clustered redirects. |
| **Keep a repo-specific skill out of other repos** | `rematch policy scope set <skill> ~/repos/<repo>` | Withdraws the skill from global skill directories and loads it only inside sessions matching that repo's git remote (travels with your profile). |
| **Review waiting actions or undo automatic trials** | Press `alt+e` (`/rematch review`) in omp, `/rematch:rematch-review` in Claude Code, or `rematch status --text`. | Opens the `◆ rematch · review` overlay: **Needs you** shows the sandbox dry-run observation and colored diff (`a` approve, `d` decline, `i` full diff); **Applied** lists every automatic trial and probe verdict with one-key undo (`u`). |

## What stays under your control

<ul class="rm-never">
	<li><strong>Scripts and write-capable subagents wait for you</strong> (unless you set a standing <code>rematch policy auto</code> rule). Scripts are staged non-executable (<code>0644</code>) with an OS sandbox dry-run summary shown in the review panel; data-only hooks and read-only subagents start as scoped trials listed under <strong>Applied</strong> with one-key undo.</li>
	<li><strong>Nothing changes beyond your machine on its own.</strong> Team and fork changes are local branches and optional PRs; nothing is merged for you.</li>
	<li><strong>Your <code>AGENTS.md</code> is yours.</strong> A repo's <code>AGENTS.md</code> is never written by personal adoption, and your personal <code>~/.omp/agent/AGENTS.md</code> is only updated inside marked blocks after your hash-bound approval.</li>
	<li><strong>Nothing is called verified.</strong> An entry is <code>kept</code> only after four clean completed sessions of actual use or a supporting comparative probe, and its counts are shown raw.</li>
	<li><strong>Instant kill switch:</strong> <code>/rematch off</code>, <code>rematch off</code>, or <code>REMATCH=0</code> withdraws every rematch skill, agent, hook and unchanged instruction block immediately.</li>
</ul>
